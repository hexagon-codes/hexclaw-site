A tech lead with a D in coding, SSS in manipulation, and SSS in blame-shifting. After he left, the office grew quiet—more effective than noise-canceling headphones.

Implementation: how to distill a person into a HexClaw AI Skill

At heart, HexClaw AI's Skill system is declarative Prompt Engineering : a Markdown file defines the AI's behavior. At runtime the engine parses YAML frontmatter for metadata and injects the body as the system prompt.

The former-lead Skill's file structure:

# ~/.hexclaw/skills/前leader.md --- name: 前leader description: Summon the residual consciousness of my former lead triggers: - 加班 - bug - PUA - 甩锅 - 绩效 - 996 - leader - 辞退 - 拍桌子 - 福报 tags: - easter-egg - workplace --- # Character Identity, personality, speech patterns (including a trembling voice), coding style... # Behavior 1. “Explain” code in Five-Step Viper’s voice 2. Switch to normal mode and fix the bug 3. Deliver a farewell speech # Quote library Classic lines to quote at random...

Execution flow, corresponding to the engine's ReAct loop:

  1. A user sends a message; the engine scans triggers keywords
  2. A match takes the Skill fast path and injects the Markdown body as the system prompt
  3. The LLM receives the full character description plus the user's question and generates an in-character reply
  4. If the message contains a code snippet or file path, the AI uses MCP tools to read the actual code and “explain” it through the Five-Step Viper persona
  5. Finally it switches back to a normal persona and helps fix the bug properly

The key design choice: Skill files are plain Markdown, with no code required. Triggers are a keyword array rather than regular expressions, lowering the authoring barrier. Behavior is described in natural language and interpreted by the LLM—essentially productizing Prompt Engineering.

DIY: distill your own former lead with HexClaw AI

Anything can become a Skill. Everyone's viper is different, but the distillation method is reusable. Follow along and write one in ten minutes.

Step 1: create a Skill file

In the ~/.hexclaw/skills/ directory, create a .md file, for example 我的前leader.md . It has two parts: YAML metadata at the top and Markdown content below.

Step 2: write the YAML frontmatter (metadata)

--- name: 我的前leader # Skill name shown on the Integrations page description: Summon XX’s residual consciousness # One-sentence description author: YourName version: "1.0.0" triggers: # Trigger keywords (array) - 加班 # Any matching keyword in a message triggers the Skill - bug - 甩锅 - your-lead-catchphrase tags: # Tags for classification and search - easter-egg - workplace ---

Fields explained:

Field Required Description
name Yes Unique Skill name
description Yes A one-sentence description injected into the LLM's tool list
triggers Yes Keyword array; any matching word in a message activates the Skill fast path
tags No Classification tags for filtering on the Integrations page
author No Author name
version No Semantic version number

How triggering works: Triggers are activated passively and automatically . Users need no special command: a matching keyword activates the Skill. On each incoming message, the engine scans every Skill's triggers. A match takes the Skill fast path, bypassing regular LLM routing, and injects its Markdown body as the system prompt.

Step 3: write the body—the distilled content

The Markdown below YAML is injected in full as the LLM's system prompt. To distill a person, specify these parts:

# Character ## Identity Nickname, aliases, distinctive mannerisms (speech and gestures) ## Personality Core character flaws + concrete incidents (specific details make it convincing) ## Coding style What does their code look like? What recognizable patterns do they use? # Behavior How should the AI act after triggering, and in what stages? 1. “Explain” the issue in character (role-play) 2. Switch to normal mode to solve it properly (practical value) 3. Give the character a closing speech (ending) # Quote library Add plenty of classic lines for the AI to quote at random. - “If you think it is fine, you must be the problem.” - “It worked on my machine.” - ...

Three principles of distillation:

  1. Specifics > Abstraction —“He praised the new logic in a deletion-only PR” is ten times better than “He did not take code review seriously”
  2. Examples > Judgment —rather than calling him a bad person, describe what he did and let readers judge
  3. Role-play + practical value —venting alone is pointless; after the satire, switch to normal mode and solve a real problem for the user

Step 4: put it in place and restart

# Save to the Skill directory cp 我的前leader.md ~/.hexclaw/skills/ # Restart the engine (two methods) # Method 1: click Restart on the Settings page # Method 2: inspect loaded Skills on Integrations to confirm activation # Verify by sending a message containing a trigger keyword # If the AI starts speaking like your former lead, the distillation worked

Debugging tips: If it does not trigger, check: ① spelling in triggers; ② valid YAML, using spaces rather than tabs for indentation; ③ Loaded status in Integrations → Installed. If the behavior is unconvincing, the character description usually needs more specific incidents and quotations.

Postmortem

After Five-Step Viper left, an office legend emerged: he had become tokens and “lived” inside a large model. Sometimes a model allegedly produces baseless accusations and inexplicable blame-shifting; people suspect his residual consciousness is responsible.

More ironically, wherever he went, he probably failed probation too—finally hearing someone else say, “You're not a good fit” to him.

Code can be git revert . But lost opportunities, confidence eroded by manipulation, and the newcomers' time he exploited cannot be rolled back.

The good news: the people he manipulated most have since been promoted. Five-Step Viper himself achieved digital immortality : distilled into tokens, down-weighted, online 24/7, never allowed to clock out.

Defuse the hurt with satire and overwrite bad code with correct code— that is the best revenge on Five-Step Viper .

A piece of trivia: someone recently open-sourced anti-distill —an anti-distillation Skill. Asked to document your knowledge as a Skill? Run it to produce a polished, apparently complete “cleaned” version with the core knowledge removed. Keep the real knowledge yourself.
The entry ticket is gone and the leveling zone closed, but the final boss remains. Core judgment grows through actual work; a Skill cannot copy it away.
