The Complete HexClaw AI Guide: From Zero to a Local AI Agent That Gets Work Done in Five Minutes (with Model Recommendations)

Configure local Ollama or a cloud API from scratch, create an agent assistant, and add knowledge bases and skills. Start using your own desktop AI assistant in five minutes.

In the previous article, we unpacked HexClaw AI's six repositories and explained the architecture layer by layer, from the underlying framework to the desktop client.

Understanding the architecture is one thing; finding out whether the product is useful takes hands-on use. This article focuses on operation, not theory: from installation to having AI read files, query a knowledge base, and connect to Feishu, all in five minutes.

By the end, you will have a free, open-source AI agent running on your own computer, with data staying on your machine.

Installation: One Command

Download from the official website: hexclaw.net (copy it into your browser; macOS, Windows, and Linux are all supported)

macOS:

brew tap hexagon-codes/tap && brew install --cask hexclaw

No Homebrew? Use curl:

curl -fsSL https://raw.githubusercontent.com/hexagon-codes/hexclaw-desktop/main/install.sh | bash

Windows / Linux: Visit hexclaw.net to download the appropriate installer (.exe / .deb / .AppImage), then double-click to install.

After installation, open HexClaw AI to see the setup wizard. Three steps, done in 30 seconds.

Tool Calling: More Than Talk

I asked, “What files are in my hexclaw directory?” HexClaw called the list_directory tool and actually read the local filesystem:

It did not invent the answer: it read the files. Tool-call results are collapsed beneath the message; expand them to see the full content.

The mechanism behind tool calling is MCP (Model Context Protocol). Think of it as a universal USB adapter: when AI needs to operate on files, plug in the filesystem adapter; when it needs to query a database, plug in the database adapter. HexClaw AI supports MCP natively: configure it and use it, without writing code.

The process is automatic: you send a message → the LLM decides which tool to call → the engine routes the request to the corresponding MCP server → the result comes back → the LLM generates a reply based on that result. If one step is not enough, the loop continues: search, then read, then summarize, making successive calls until it reaches a final answer. This is the ReAct tool loop.

Next, I asked, “What did I buy last year?” I had mentioned this casually in an earlier conversation. HexClaw remembered:

It recalled the previous conversation and answered correctly. Rather than stretching the context window, this uses long-term memory: the information was actually stored and can be recalled in a new conversation. The next section explains how memory works.

Knowledge Bases and Memory: Two Ways AI Remembers

HexClaw “remembers” things in two ways: through material you deliberately provide and through information it learns from conversations.

Knowledge base: you upload, and it answers from sources. Open the knowledge-base page and drop in a PDF, TXT, or Markdown file to create an index automatically:

During later conversations, AI uses vector retrieval to find the most relevant passages in your documents and injects them into the prompt. The earlier answer about Hangzhou cuisine came from the knowledge base. It was answering from sources rather than making things up. This is RAG: retrieval-augmented generation.

Memory: key information from conversations is stored and recalled automatically.

After a conversation, the engine analyzes it asynchronously and extracts information worth remembering. In the next conversation, relevant memories are automatically added to the context, and HexClaw “remembers.” You can also add, edit, and delete memories manually.

Put simply, a knowledge base is an external reference library, while memory is the AI's notebook. One stores documents; the other stores the useful essence of conversations.

Configure a Feishu Bot in Three Minutes

To make HexClaw AI available in Feishu, create an internal application on the Feishu Open Platform. The process is straightforward:

1. Create an application and obtain its credentials. Go to the Feishu Open Platform and create an enterprise internal application. Under “Credentials & Basic Info,” obtain the App ID and App Secret:

2. Configure permissions. On the “Permissions” page, click “Batch Import/Export Permissions” and paste the JSON below to import the complete permission set in one go. It covers sending and receiving messages, reading group and private chats, resource files, group information, user information, document access, and more:

{ "scopes": { "tenant": [ "im:message", "im:message:send_as_bot", "im:message.group_at_msg", "im:message.group_at_msg:readonly", "im:message.p2p_msg", "im:message.p2p_msg:readonly", "im:message:readonly", "im:resource", "im:chat", "im:chat:readonly", "contact:user.base:readonly", "document:readonly" ], "user": [ "docs:document:readonly" ] } }

3. Configure event subscriptions. On the “Events & Callbacks” page, select “Receive events through a persistent connection” and add the im.message.receive_v1 event to receive group and private-chat messages:

4. Publish a version. On the “Version Management & Release” page, create a version, select “Bot” as the default desktop capability, and submit it for release:

5. Return to HexClaw AI. Create a Feishu instance on the IM Channels page, enter the App ID and App Secret, and enable it. When you see the green “Running” status, you are done.

DingTalk / Discord / Telegram follow similar setup processes: create a bot application on the relevant platform, obtain its credentials, and enter them on HexClaw AI's IM Channels configuration page.

Model Configuration: Cloud and Local, Your Choice

HexClaw AI lets you configure several models at once and route between them automatically according to a policy. At the top of Settings, choose a default model and a routing policy (cost first / quality first); manage providers at the bottom:

Want data to stay on your machine? Use local models. With built-in Ollama management, you can search for a model and download it directly:

Free, offline, and with data staying on your machine. The application warms the model up automatically at startup, so you can chat as soon as it opens. The appendix provides detailed recommendations for model choice and hardware.

The central idea is simple: configure both cloud and local models and choose “Cost First” routing. Simple questions use a free local model; complex questions switch to the cloud automatically. For sensitive data, keep the entire process local, with no API requests leaving your computer.

Skills and MCP: Two Extension Layers

HexClaw AI's capabilities are not hard-coded. It has two extension mechanisms.

A Skill defines a high-level role: Markdown specifies its trigger conditions, system prompt, and available tools. After installing the cron-scheduler skill, say “Collect the news for me every day at 10,” and AI calls the skill to create a scheduled task. You do not need to know the skill exists; AI decides whether to use it.

MCP (Model Context Protocol) provides the low-level hands and feet. Each MCP server exposes a set of tools; the engine gathers all their definitions at startup, and AI calls them as needed. Below is the built-in filesystem MCP server, providing 14 tools:

For an analogy, a Skill means “you hired a professional accountant,” while MCP means “you gave the accountant a calculator and Excel.” One defines the role and strategy; the other provides concrete operational capabilities. You can use either alone, but they are strongest in combination.
