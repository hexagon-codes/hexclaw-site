«چۈش كۆرىدىغان» Agent ئەسلەتمىسى: Claude بىلەن ChatGPT بۇلۇتتا، HexClaw ئۆز كومپيۇتېرىڭىزدا چۈش كۆرىدۇ

بۇلۇتقا چىقمايدىغان، git diff بىلەن كۆرگىلى بولىدىغان يەرلىك يولغا قويۇش: ئۈچ قاتلام، ئۈچ ئۆلچەملىك ئەسلەش ۋە ئىككى باسقۇچلۇق چۈش كۆرۈش. بىر «مەن قەيەردە» ئەسلەتمىسىگە ئەگىشىپ، يەرلىك Agent نىڭ ئۇيقۇ دەۋرىدە ئۇچۇرنى قانداق رەتلەيدىغانلىقى، ئايرىپ چىقىرىدىغانلىقى ۋە ئۇنتۇيدىغانلىقىنى كۆرىمىز.

ئالدى بىلەن WeChat تا ئېلان قىلىنغان بۇ ماقالە تۇنجى قېتىم WeChat رەسمىي ھېسابىدا ئېلان قىلىنغان: 「hexclaw」، ID: hexclaw، رەسمىي تېخنىكا سەھىپىسى · ئېلان ۋاقتى: 2026-06-27 · تەخمىنەن 11 مىنۇتلۇق ئوقۇشلۇق
WeChat تىكى خەنزۇچە ئەسلى ↗

بىر نەچچە كۈن ئىلگىرى HexClaw نىڭ ئەسلەتمە ھۆججىتىنى ۋاراقلاپ، مۇنداق بىر قۇرنى كۆردۈم:

- 我在西湖区 <!--m:subj=所在地; vf=2026-06-20;conf=0.90;hc=2-->

قۇر ئاخىرىدىكى HTML ئىزاھى Markdown كۆرسىتىلگەندە كۆرۈنمەيدۇ. داۋامىنى كۆرۈپ، «شىخۇ رايونى» دېگەن ئەسلەتمىنىڭ يەنىلا بارلىقىنى بايقىدىم؛ پەقەت كۈچتىن قالغان ۋاقتى يېزىلىپتۇ، چۈنكى ئالدىنقى ھەپتە ئۇ يەرگە بېرىپ كەلگەنىدىم. ھازىر كۈچكە ئىگە بولغىنى كېيىن يېزىلغان «مەن يۈخاڭ رايونىدا» دېگەن ئەسلەتمە، ئۇ مەن ئادەتتە تۇرىدىغان جاي. ئۇ شىخۇ رايونىنى ئۆچۈرمەپتۇ، پەقەت ۋاقىت تامغىسى بېسىپتۇ.

يېقىندا Claude بىلەن ChatGPT ئەسلەتمە سىستېمىسىغا «چۈش كۆرۈش»نى قوشتى: ئارقا سۇپىدا سىز ئېيتقان گەپلەرنى ئۆزلۈكىدىن رەتلەپ، بىر شەخسىي ئارخىپقا ئايلاندۇرىدۇ. Anthropic مايدا ئېلان قىلغىنىنى Claude Dreaming، OpenAI ئىيۇندا ئېلان قىلغىنىنى Dreaming V3 دەپ ئاتىدى؛ ھەر ئىككىسى ئىنسان ئۇخلىغاندا مېڭىنىڭ ئەستە ساقلاشنى مۇستەھكەملەش جەريانىنى مىسال قىلدى. مەنمۇ HexClaw غا شۇنداق ئەسلەتمە سىستېمىسى قوشماقچى بولدۇم. ئەمەلىي ئىشلەشكە كىرىشكەندە، ئىككى نۇقتىنى قەستەن باشقىچە قىلدىم:

  • ئەسلەتمە رەتلەشنىڭ ھەر بىر قەدىمى cat بىلەن كۆرەلەيدىغان، git diff بىلەن سېلىشتۇرالايدىغان ئاددىي تېكىستكە يېزىلىدۇ؛ كۆرگىلى بولمايدىغان بۇلۇتقا ئەمەس.
  • «چۈش كۆرۈش»نىڭ ھەقىقەتەن توقۇلما چىقىرىشى مۇمكىن بولغان قىسمىنى، يەنى LLM غا ئەسلەتمىنى قايتا يازدۇرۇشنى، چېگراسى بار بىر قەپەسكە سولىدىم. ئۇ سۈكۈتتىكى ھالەتتە قۇلۇپلانغان، ئېچىش-تاقاشنى سىزگە قالدۇردۇم.

بۇ ئىككىسى سېتىش نۇقتىسى ئەمەس، ئۆزۈم خاتىرجەم ئىشلىتىش ئۈچۈن بەلگىلىگەن ئاخىرقى چەك. ئەمدى باشتىكى «تۇرۇشلۇق جاي» ئەسلەتمىسىگە ئەگىشىپ، ئۇنىڭ HexClaw دا قانداق بىر ئۆمۈرنى باشتىن كەچۈرىدىغانلىقىنى كۆرەيلى.

ئاۋۋال پۈتۈن بىنانى كۆرەيلى: ئۈچ قەۋەت ۋە ئالتە تۈر

ئەسلەتمىگە ئەگىشىشتىن بۇرۇن پۈتۈن قۇرۇلمىنى كۆرۈش كېرەك. HexClaw نىڭ ئەسلەتمىسى بىر چوڭ كۆلچەك ئەمەس، ئۈچ قەۋەتلىك بىنا. بۇ قۇرۇلما مەشغۇلات سىستېمىسىنىڭ ئىچكى ساقلىغۇچ باشقۇرۇش ئىدىيەسىدىن پايدىلىنىدۇ: Letta / MemGPT ئۇنى core / recall / archival دەپ ئاتايدۇ؛ ماھىيىتى مەۋھۇم ئىچكى ساقلىغۇچ باشقۇرۇش ئۇسۇلى بىلەن ئەسلەتمىنى باشقۇرۇش.

  • دائىمىي قاتلام، ئۈستۈنكى قەۋەت: سىز كىم، بەلگىلىگەن قاتتىق قائىدىلىرىڭىز ۋە ئۇزاق مۇددەتلىك مايىللىقىڭىز. سۆھبەت باشلىنىشىدا مۇقىم سۈرەت قىلىپ توڭلىتىلىپ كىرگۈزۈلىدۇ، ھەر ئايلانمىدا بولۇشى كاپالەتلەندۈرۈلىدۇ.
  • ئىزدەپ ئەسلەش قاتلىمى، ئوتتۇرا قەۋەت: «يۈخاڭ رايونىدا»، «ئالدىنقى ھەپتە RAG خاتالىقىنى تۈزەتتى»، «تېخنىكا توپلىمى Go» دېگەندەك پارچە پاكىتلار. ھەر ئايلانمىدا ھەممىسى كىرگۈزۈلمەيدۇ؛ نۆۋەتتىكى سوئالغا قاراپ ئۈچ ئۆلچەمدە نومۇر بېرىپ، ئەڭ مۇناسىۋەتلىك بىر نەچچىسى ئەسلىتىلىدۇ.
  • ئەسلى قاتلام، يەر ئاستى: بارلىق سۆھبەتلەرنىڭ تولۇق تېكىستى. ئادەتتە ئۆزگەرمەيدۇ، لازىم بولغاندا تولۇق تېكىست ئىزدەش ئارقىلىق تېپىلىدۇ.

ئەسلەتمىنىڭ قايسى قاتلامغا چۈشىدىغانلىقىنى ئۇنىڭ تۈرى ئۆزلۈكىدىن بەلگىلەيدۇ، قولدا تولدۇرۇش ھاجەتسىز. قائىدە، سالاھىيەت، بۇيرۇق ۋە مايىللىق دائىمىي قاتلامغا؛ ئادەتتىكى پاكىت بىلەن كونتېكىست ئىزدەپ ئەسلەش قاتلىمىغا كىرىدۇ. ھەر بىر ئەسلەتمىنىڭ (user, persona) تەۋەلىكىمۇ بار. Feishu غا ئۇلىنىپ بىر نەچچە ئادەم بىر Agent نى ئورتاق ئىشلەتسىمۇ، كىشىلەرنىڭ ئەسلەتمىلىرى ئارىلاشمايدۇ.

بۇ بىنا ئىچىدىكى ھەر بىر ئۆزگىرىش، سىز ئېغىز ئۇچىدا ئېيتقان، AI ئۆزى خاتىرىلىگەن، كېچىدە چۈش كۆرۈپ رەتلىگەن ياكى سىز ھۆججەتتە قولدا ئۆزگەرتكەنلىرىڭىزنىڭ ھەممىسى بىرلا «يەككە يازغۇچ»تىن ئۆتۈپ ئۆچرەت بىلەن دىسكىغا يېزىلىدۇ. يېزىش ئاتوملۇق، ئۆزئارا قاپلىمايدۇ؛ ھەتتا قولدا ئۆزگەرتكەن تۈرلەرنىمۇ ئاۋۋال سېلىشتۇرۇپ، قارىغۇلارچە قاپلىمايدۇ. تۆۋەندە قاتلاممۇقاتلام كۆرىمىز؛ بۇ رەسىمدىنمۇ پۈتۈن كۆرۈنۈشنى ئىگىلىيەلەيسىز.

ساقلاش: بىر قۇر ئادەتتىكى گەپ، ئاخىرىدا يوشۇرۇن ئىزاھ

سىز «مەن يۈخاڭ رايونىدا» دېسىڭىز، HexClaw ئۇنى خاتىرىلەيدۇ. قەيەردە ساقلاش ھەققىدە ساھەدە ئىككى يول بار: ChatGPT بۇلۇتتا ساقلايدۇ، تەڭشەكتىن تىزىملىكنىلا كۆرەلەيسىز؛ Claude Code يەرلىك ھۆججەتتە ساقلايدۇ. HexClaw كېيىنكى يولنى تاللىدى، بىراق قوشۇمچە بىر ئىش قىلدى: ھەر بىر ئەسلەتمىگە كۆرۈنمەيدىغان بىر يوشۇرۇن ئىزاھ تىكتى، يولغا قويۇلۇشى structured_entry.go دا.

ئۇ دەل باشتىكى قۇر ئاخىرى ئىزاھى: subj پاكىتنىڭ «سۇبيېكتى»، بۇ يەردە تۇرۇشلۇق جاي؛ vf كۈچكە ئىگە بولغان ۋاقىت؛ conf ئىشەنچ دەرىجىسى؛ hc قانچە قېتىم ئەسلىتىلگەنلىكى. بىر مەيدانمۇ سانلىق مەلۇمات ئامبىرىغا تايانمايدۇ، ھەممىسى Markdown قۇر ئاخىرىدىكى ئىزاھقا يوشۇرۇنغان. ھۆججەت يەنىلا cat بىلەن كۆرەلەيدىغان، تەھرىرلىيەلەيدىغان، git diff بىلەن سېلىشتۇرالايدىغان ئاددىي تېكىست، ئەمما ئەسلەتمە قۇرۇلمىلىق بولدى: رەتلىگىلى، سېلىشتۇرغىلى ۋە كۈچتىن قالغانلىقىنى بەلگىلىگىلى بولىدۇ. كونا تۈردە بۇ ئىزاھ يوقمۇ؟ پارس قىلغاندا مەيدانلار نۆل قىممەت ئالىدۇ، يەنىلا نورمال ئىشلەيدۇ.

نېمىشقا مېتا سانلىق مەلۇماتنى سانلىق مەلۇمات ياكى ۋېكتور ئامبىرىغا سالمايمىز دەپ سورىشىڭىز مۇمكىن. چۈنكى ئامبارغا كىرگەندىن كېيىن cat، git diff ياكى قولدا تەھرىرلەش ئاسان بولمايدۇ. HexClaw «ئاددىي تېكىست + قۇر ئىچى ئىزاھ + يەككە يازغۇچ بىلەن تەرتىپلىك دىسكىغا يېزىش» ئارقىلىق قۇرۇلمىنى ساقلاپ، «كۆرەلەيسىز، ئۆزگەرتەلەيسىز، كەينىگە ياندۇرالايسىز» دېگەن ئالاھىدىلىكنى قوغدايدۇ. بۇ ئاڭلىق تاللاش: بىر ئاز يېزىش ئۆتكۈزۈشچانلىقىنى بېرىپ، پۈتۈن جەرياننىڭ ئوچۇق بولۇشىنى ئالىدۇ. ئۆز كومپيۇتېرىڭىزدا ئىشلەپ، كېچىدە ئۆز ئەسلەتمىسىنى ئۆزى ئۆزگەرتىدىغان سىستېما ئۈچۈن بۇ مۇۋاپىق سودىدۇر.

پىكىر ئۆزگىرىشى: كونىسىنى ئۆچۈرمەي، كۈچتىن قېلىش تامغىسى بېسىش

ئاۋۋال بۇ قۇرۇلمىنىڭ قانداق شەكىللەنگەنلىكىنى ئېيتاي. دەسلەپ ئۇ append-only ئېقىملىق خاتىرە ئىدى: ھۆججەتكە قۇر قوشاتتى، كەينىگە قارىمايتتى. ئۇزاق ئىشلىتىلگەندە ئىككى مەسىلە چىقتى: زىت پاكىتلار توقۇنۇشاتتى، بىر ئىشقا ئىككى قىممەت ئېيتىلسا قايسىسىغا ئىشىنىدۇ؟ يەنە توپلانغانسېرى قالايمىقانلىشاتتى. كېيىنكى supersede ئارقىلىق تارىخ ساقلاش ۋە كېچىلىك چۈش كۆرۈپ رەتلەش دەل شۇ ئىككى مەسىلىدىن كەلدى.

سىز ئادەتتە يۈخاڭ رايونىدا تۇرىسىز، بىر نەچچە كۈندىن كېيىن شىخۇ رايونىغا بېرىپ Agent غا دەيسىز. بۇ ۋاقىتتا نۇرغۇن ئەسلەتمە سىستېمىسى مەن خاتىرجەم بولالمايدىغان ئىشنى قىلىدۇ: «يۈخاڭ رايونى»نى بىۋاسىتە «شىخۇ رايونى»غا ئۆزگەرتىدۇ. ChatGPT Dreaming مۇ بۇ تۈرگە كىرىدۇ: ئارقا سۇپىدا قايتا يېزىپ، كونا قىممەت يوقىلىدۇ، زادى نېمە ئۆزگەرگەنلىكىنى قايتا كۆرۈشمۇ قىيىن.

HexClaw قاپلىمايدۇ. ئاۋۋال upsert.go دا تەكرارلىقنى باھالايدۇ: يېڭى گەپ بىلەن ساقلانغان بىر تۈرنىڭ ھەرپ جۈپى ئوخشاشلىق دەرىجىسى 0.65 تىن ئاشسا، شۇ ئىشنىڭ قايتا يېزىلىشى ھېسابلىنىدۇ. ئەمما «تۇرۇشلۇق جاي» سۇبيېكتىدا يۈخاڭ بىلەن شىخۇ ئوخشاش ئەمەس، بۇ زىتلىق. شۇڭا قاپلاشنىڭ ئورنىغا supersede، يەنى ۋاقىت بويىچە ئورۇن بېسىش يولىغا كىرىدۇ. ھەر بىر پاكىتنىڭ «كۈچكە ئىگە ۋاقىت كۆزنىكى» بار؛ زىتلىق بولسا يوقىتىش ئەمەس، ئورۇن بېسىش بولىدۇ. Zep / Graphiti بۇنى bi-temporal، ئىككى ۋاقىت ئوقى دەپ ئاتايدۇ:

// 召回默认只取"当前有效"的条目 func IsCurrentlyValid(e, now) bool { if e.ValidTo != nil && !now.Before(*e.ValidTo) { return false // 已被取代,失效 } return true }

«يۈخاڭ رايونى» ئۆچۈرۈلمەيدۇ؛ يوشۇرۇن ئىزاھىغا vt، يەنى كۈچتىن قالغان ۋاقىت قوشۇلىدۇ. «شىخۇ رايونى» يېڭىدىن يېزىلىپ، sup بىلەن كونىسىنى كۆرسىتىدۇ. كېيىن ئەسلەتكەندە سۈكۈتتىكى ھالەتتە پەقەت نۆۋەتتە كۈچكە ئىگە تۈر تاللىنىدۇ: شىخۇدا بولسىڭىز شىخۇ دەپ جاۋاب بېرىدۇ؛ يۈخاڭغا قايتسىڭىز يەنە بىر supersede قىلىپ تۇرۇشلۇق جاينى قايتۇرىدۇ. قايسى كۈنى يۈخاڭدا، قايسى كۈنى شىخۇغا بارغانلىقىڭىزنىڭ ھەممىسى ھۆججەتتە تولۇق ساقلىنىدۇ؛ git log دىن ئېنىق كۆرەلەيسىز.

قاپلاش تارىخنى ئۆچۈرىدۇ؛ ئورۇن بېسىش تارىخقا ۋاقىت تامغىسى باسىدۇ. بىرىنچىسىگە پەقەت ئىشىنىسىز، ئىككىنچىسىنى تەكشۈرەلەيسىز.

ئەسلەش: دائىمىي قاتلامنى توڭلىتىش، ئۈچ ئۆلچەملىك نومۇر ۋە تەشەببۇسكار ئەسلەش

ئەسلەتمە لازىم بولغاندا، ئۈچ قەۋەت ئۆز ۋەزىپىسىنى ئورۇندايدۇ.

ئۈستۈنكى دائىمىي قاتلام ھەر ئايلانمىدا كىرگۈزۈلىدۇ. سۆھبەت باشلىنىشىدا ماتور ئۇنى بىر مۇقىم سۈرەتكە توڭلىتىدۇ، token خامچوتىغا ئاساسەن تاللايدۇ: pinned تۈرلەر ئالدىن، ئاندىن مۇھىملىق، ئاخىرىدا يېقىنلىق بويىچە. بۇ resident.go دا. قاتتىق قائىدە بىلەن سالاھىيىتىڭىز ھەر ئايلانمىدا بولىدۇ، «تەلىيىگە ئىزدەپ تېپىش»قا تايانمايدۇ.

ئوتتۇرىدىكى ئىزدەپ ئەسلەش قاتلىمى ئېھتىياج بويىچە تاللايدۇ. ئەسلەتمە كۆپەيسە ھەممىسىنى سىغدۇرغىلى بولمايدۇ. ئەڭ ئاددىي ئۇسۇل ۋېكتور ئوخشاشلىقى بىلەن تاللاش: نۆۋەتتىكى سوئالغا كىم ئەڭ ئوخشىسا شۇ ئەسلىتىلىدۇ. بىراق بۇ يولدىكى مەسىلىگە تېزلا يولۇقتۇم: ساپ ئوخشاشلىق «مۇھىم، ئەمما كونا» ئىشنى كۆمۈۋېتىدۇ. مەسىلەن ئىككى ئاي ئىلگىرى «كونا API بەزىدە ئىشلىمەي قالىدۇ، ۋاقىت چەكلىمىسى بىلەن زاپاس تەدبىر قوشۇشنى چوقۇم ئۇنتۇما» دەپ ئالاھىدە ئەسكەرتكەنسىز. كېيىنكى سوئالىڭىز ئۇ گەپكە مەنىدىن ئانچە يېقىن ئەمەس، ئەمما شۇ ئەسكەرتىشنى تاپمىسا يەنە ئوخشاش ئازگالغا چۈشىشىڭىز مۇمكىن. شۇڭا HexClaw ئۈچ ئۆلچەملىك نومۇر بېرىدۇ. recency × importance × relevance دەل Stanford نىڭ Generative Agents ماقالىسىدىكى نومۇرلاش ئۇسۇلى؛ recall/entry.go دا يولغا قويۇلغان:

// 三维加权,确定性,零 LLM Score = 新近度 + 重要度 + 相关度 // 重要度 = 类型先验 + 显著性 + 召回频次 // 规则/身份 1.0 · 指令 0.8 // 偏好 0.6 · 普通事实 0.4
  • مۇناسىۋەت دەرىجىسى: ۋېكتور مودېلى سەپلەنسە cosine 0.7 ۋە ئاچقۇچلۇق سۆز BM25 0.3 نى ئېغىرلىق بىلەن ئارىلاشتۇرىدۇ؛ سەپلەنمىسە پەقەت ئاچقۇچلۇق سۆزگە يۇمشاق تۆۋەنلەيدۇ، چۆكمەيدۇ.
  • يېقىنلىق: ئېكسپونېنتسىيال ئاجىزلاش، يېرىم ئۆمرى 30 كۈن.
  • مۇھىملىق: LLM نىڭ دەرھال باھا بېرىشىگە تايانمايدۇ؛ «تۈر ئالدىنقى قىممىتى + روشەنلىك + ئەسلەنگەن قېتىم سانى» بىلەن ھېسابلىنىدۇ. «ئاللېرگىيە»، «جەزمەن»، «چوقۇم» قاتارلىق سۆزلەر بولسا نومۇر قوشۇلىدۇ، شۇڭا مۇھىم يېڭى پاكىت تۇنجى قېتىمدىلا ئەسلەشكە يېتەرلىك نومۇر ئالىدۇ. ھەر مۇۋەپپەقىيەتلىك ئەسلەشتە يەنە بىر ئاز كۆپىيىپ، يۇقىرى چەككە توختايدۇ.

«ۋاقىت چەكلىمىسى بىلەن زاپاس تەدبىر قوشۇشنى چوقۇم ئۇنتۇما» مۇھىم كونا ئەسكەرتىش. «چوقۇم» دېگەن سۆز روشەنلىك قوشۇمچىسىنى قوزغاپ، مۇھىملىقنى ئۆستۈرىدۇ؛ كونا بولسىمۇ، بۈگۈنكى سوئالغا مەنىدىن ئەڭ ئوخشاش بولمىسىمۇ، ئۈچ ئۆلچەم ئېغىرلىقى ئۇنى يۇقىرىغا چىقىرالايدۇ. بۇ يەردە قەستەن قىلىنغان يەنە بىر لايىھە بار: ئۈچ ئۆلچەمنىڭ دائىرىسى ئوخشاش ئەمەس. مۇھىملىق تۈر ئالدىنقى قىممىتى، روشەنلىك ۋە ئەسلەش قوشۇلۇپ 2.0 غا يېتەلەيدۇ؛ يېقىنلىق ۋە مۇناسىۋەتنىڭ ھەر بىرى 1.0 دا توختايدۇ. دېمەك يېتەرلىك مۇھىم ئىش نومۇردا يېتەرلىك ئوخشاش ئىشتىن تەبىئىي ئۈستۈن كېلەلەيدۇ. ساپ ئوخشاشلىق «ئوخشىمامدۇ؟» دەپلا سورايدۇ، HexClaw «مۇھىممۇ؟» دەپمۇ سورايدۇ؛ بۇ مۇھىملىق سۆز بىلەنلا دېيىلمەي، ھېسابلىنىدۇ.

يەر ئاستىدىكى ئەسلى قاتلام لازىم بولغاندا ۋاراقلىنىدۇ. بۇ يەردە ئىككى مۇستەقىل يول بار، ئارىلاشمايدۇ: ئىشەنچلىك تاللاپ رەتلەنگەن پاكىتلار ھەر ئايلانمىدا ئۆزلۈكىدىن كىرگۈزۈلىدۇ، ئەسلى سۆھبەتنىڭ تولۇق تېكىستى ئېھتىياج بويىچە ئىشلىتىلىدۇ. مودېل ئۆزى ئىزدەشنى خالىغاندىن سىرت، HexClaw جاۋاب بېرىشتىن بۇرۇن تارىخىي سۆھبەتنى ئۆزى بىر قېتىم ئىزدەيدۇ. بۇ active_recall.go دا، سۈكۈتتىكى ھالەتتە ئوچۇق؛ «ئەستە بولۇشى كېرەك» كونا پارچىلارنى ئالدىن چىقىرىدۇ. ئەمما چەكلىك: ئەڭ كۆپ 3 تۈر، 1.5 سېكۇنت ۋاقىت چەكلىمىسى، ساپ يەرلىك تولۇق تېكىست ئىزدەش ۋە نۆل LLM. ئارقا-ئارقىدىن 3 قېتىم مەغلۇپ بولسا 60 سېكۇنت توختايدۇ؛ پەقەت بىرگە-بىر پاراڭدا ئىجرا بولىدۇ. مەغلۇپ بولسا جىمجىت چېكىنىپ، جاۋابىڭىزنى ھەرگىز توسمايدۇ.

چۈش كۆرۈش: رەتلەيدۇ، ئەمما توقۇلما چىقىرىدىغان يېرىمىنى قۇلۇپلىدىم

يۇقىرىقىلار كۈندىلىك ئىشلىتىشكە يېتىدۇ. ئەمما ئەسلەتمە توپلانغانسېرى پارچىلىنىدۇ: بۇ ھەپتە بىر تۈرنى ئۈچ قېتىم تىلغا ئالغان، بەش پارچە مايىللىق ئېيتقان بولۇشىڭىز مۇمكىن. ئۇلارنى دائىم بىر پاكىز گەپ ياكى مۇقىم شەخسىي ئارخىپقا رەتلەش كېرەك. بۇ «چۈش كۆرۈش»، ماقالە نامىمۇ شۇنىڭدىن كەلگەن. HexClaw نىڭ چۈش كۆرۈشى ئىككى باسقۇچلۇق؛ پەرقى قايسى قىسمىغا LLM تېگىدىغانلىقىدا.

يېنىك باسقۇچ: مېخانىكىلىق رەتلەش، LLM غا يول يوق

يېنىك باسقۇچ reflect.go دا پەقەت يۆتكەش ۋە بەلگىلەش قىلىدۇ: يېقىن تەكرارلارنى بىرلەشتۈرۈپ چىقىرىش، زىت تۈرلەرنى كۈچتىن قالدى دېيىش، كۆپ ئەسلەنگەنلەرنى دائىمىي قاتلامغا ئۆستۈرۈش، كونىلارنى ئارخىپلاش. ئارقىسىدا lifecycle.go دىكى ئېنىق ھاياتلىق دەۋرى ھالەت ماشىنىسى بار؛ بوسۇغىلار مۇقىم، LLM ئىشلىتىلمەيدۇ:

ئاچقۇچى شۇكى، بۇ باسقۇچتا «ئاساسىي تېكىستنى قايتا يېزىش» ئىقتىدارى يوق. ئۇ پەقەت يۆتكەيدۇ ۋە بەلگىلەيدۇ، ئەسلەتمىنىڭ ھەقىقىي سۆزلىرىگە تېگەلمەيدۇ؛ شۇڭا توقۇلما چىقىرالمايدۇ. كۆپ ئەسلەنگەن پاكىت ئۆزلۈكىدىن دائىمىي قاتلامغا كۆتۈرۈلىدۇ، ئۇزاقتىن بېرى سورالمىغانلىرى تۆۋەنگە چۈشۈپ ئارخىپلىنىدۇ. پۈتۈن جەرياندا بىر قېتىممۇ مودېل چاقىرىش كېرەك ئەمەس، چاقىرىلمايدۇ.

چوڭقۇر باسقۇچ: LLM بىرىكتۈرىدۇ، ئەمما قەپەس ئىچىدە

چوڭقۇر باسقۇچ dreaming.go دالا LLM نى چاقىرىدۇ: ئۆزئارا مۇناسىۋەتلىك ۋە تەكرار پارچە ئەسلەتمىلەرنى بىر تۇتاش تۈرگە بىرىكتۈرىدۇ. بۇ ھەقىقەتەن چۈش كۆرۈشكە ئوخشايدىغان قىسىم، يېڭى تېكىست يارىتىشقا رۇخسەت قىلىنغان بىردىنبىر جاي. توقۇلما چىقىرىش ئېھتىمالى بولغاچقا، ئۇنىڭغا قاتتىق چەك قويۇلدى:

  • پەقەت ئىزدەپ ئەسلەش قاتلىمىغا تېگىدۇ، دائىمىي قاتلامغا تەگمەيدۇ. قائىدە، سالاھىيەت، pinned، كۆپ ئەسلەنگەن تۈرلەر، يەنى ≥ 3 قېتىم، ۋە ئىنتايىن يېڭى، تەخمىنەن 4.5 كۈن ئىچىدىكى تۈرلەر قاتلانمايدۇ. تەرەققىي قىلىۋاتقان ياكى ئەڭ مۇھىم نەرسە چۈش كۆرۈشتە ئۆزگەرمەيدۇ.
  • دائىرىسى چەكلىك. بىر ئايلانمىدا ئەڭ كۆپ 4 توپ بىرىكتۈرۈلىدۇ، ھەر توپتىن ئەڭ كۆپ 8 تۈر prompt غا كىرىدۇ. بىر كېچىدە پۈتۈن ئەسلەتمە ئامبىرىنى قايتا يېزىشقا يول قويۇلمايدۇ.
  • بىرىكتۈرگەندىمۇ قاپلىمايدۇ. يېڭى تۈر يەنىلا supersede ئارقىلىق تارىخنى ساقلايدۇ: كونىسىغا كۈچتىن قالدى دەپ بەلگە قويۇلىدۇ، قاتتىق ئۆچۈرۈلمەيدۇ، يېڭىسى كونىسىنى كۆرسىتىدۇ. چۈش كۆرۈش نېمىنى ئۆزگەرتتى، git diff بىلەن يەنىلا كۆرگىلى بولىدۇ.
  • prompt توقۇماسلىقنى ئېنىق بەلگىلەيدۇ. بىرىكتۈرۈش بۇيرۇقىدا بارلىق ئاچقۇچلۇق ئۇچۇرنى ساقلاش، پاكىتنى يوقاتماسلىق ۋە تىلغا ئېلىنمىغان نەرسىنى توقۇماسلىق تەلەپ قىلىنىدۇ.

قايتا قويۇش باسقۇچى ۋە پارچىلاردىن بىر «سىز»نى قۇراش

چوڭقۇر باسقۇچتىن باشقا يەنە ئىككى قەدەم بار. بىرى قايتا قويۇش باسقۇچى؛ ماتور قاتلىمىدا، ئىدىيەسى Claude Dreaming نىڭ «تارىخىي سۆھبەتنى قايتا قويۇشى»غا يېقىن: تۆۋەن چاستوتىدا كونا سۆھبەتلەرنى ۋاراقلاپ، ئۇ ۋاقىتتا توردا خاتىرىلەنمىگەن پاكىتلارنى تولۇقلايدۇ. ئىككىنچىسى شەخسىي ئارخىپ ئايرىپ چىقىرىش؛ profile.go دا سىز پارچە-پارچە ئېيتقان مايىللىق ۋە ئادەتلەر، مەسىلەن پەقەت يېرىم كېچىدە كۆرۈنۈش، دائىم ھاردىم دېيىش، گەپ ئاچسىلا Go دېيىش، بىر مۇقىم ئىشلەتكۈچى ئارخىپىغا ئايلاندۇرۇلۇپ دائىمىي قاتلامنىڭ ئۈستىگە قويۇلىدۇ. مەسىلەن «كۆپىنچە سەھەر سائەت 5 كىچە ئىشلەيدىغان ھارغىن ئىنژېنېر». ماقالە نامىدىكى «ئارخىپقا رەتلەش» شۇ. يېنىك باسقۇچ كۆپ، چوڭقۇر ۋە قايتا قويۇش باسقۇچلىرى ئاز ئىجرا بولىدۇ.

چۈش كۆرۈش Agent ئۈچۈن زادى نېمىنى ھەل قىلىدۇ؟

مېخانىزم ھەققىدە ئۇزۇن سۆزلىدۇق، ئەمدى ئەمەلىي پەرقنى ئېيتاي: چۈش كۆرىدىغان Agent بىلەن چۈش كۆرمەيدىغان Agent نىڭ پەرقى نېمە؟

  • ئەسلەتمە «ئەخلەت تارتمىسى»غا ئايلانمايدۇ. ئۇزاق ئىشلىتىلگەنچە پارچىلار كۆپىيىدۇ؛ رەتلەنمىسە شاۋقۇنغا تولۇپ، ئەسلەش توغرىلىقى تۆۋەنلەيدۇ. چۈش كۆرۈش قەرەللىك تەكرارنى چىقىرىدۇ، ئارخىپلايدۇ، بىرلەشتۈرىدۇ، دائىمىي قاتلام خامچوتى ۋە ئىزدەش كۆلچىكىنى ئىخچام ساقلايدۇ. OpenAI مۇ چۈش كۆرمىگەن ئەسلەتمىنى «junk drawer» دەپ تەسۋىرلىگەن.
  • پارچىلاردىن بىر «سىز» شەكىللىنىدۇ. بۈگۈن قېنىق رەڭنى ياخشى كۆرىدىغانلىقىڭىزنى ئېيتىسىز، ئەتىسى بىر رامكىنى سۆز كۆپ دەپ ياقتۇرمايسىز. ئايرىم كۆرگەندە پارچە، چۈش كۆرۈش ئۇلارنى مۇقىم ئارخىپقا ئايلاندۇرىدۇ؛ Agent كېيىن گەپ ئاچقاندا سىزنى چۈشىنىدىغان ئادەمگە ئوخشايدۇ، ھەر قېتىم نۆلدىن تونۇشمايدۇ.
  • ۋاقتى ئۆتكەن ئۇچۇر بىلەن جاۋاب بەرمەيدۇ. شەھەر ياكى تېخنىكا توپلىمىنى ئالماشتۇرسىڭىز، بىر نەرسىنى تاشلىسىڭىز، زىت كونا پاكىت كۈچتىن قالدى دەپ بەلگىلىنىدۇ؛ Agent نۆۋەتتە كۈچكە ئىگە تۈرنىلا ئالىدۇ.
  • سۆھبەتلەر ئارا ساۋاقنى ساقلايدۇ. قايتا قويۇش باسقۇچى كونا سۆھبەتلەرنى كۆرۈپ، «بۇ تۈردىكى ئىشتا دائىم قەيەردە يىقىلىمەن» دېگەن ئەندىزىنى ئايرىيدۇ. Harvey نىڭ دوكلاتىدا Claude Dreaming ئېچىلغاندىن كېيىن قايتا-قايتا مەغلۇپ بولغان قانۇن لايىھە يېزىش ۋەزىپىسىنىڭ تاماملىنىش نىسبىتى تەخمىنەن 6 ھەسسە ئاشقان؛ Agent ئوخشاش خاتالىقنى ھەر قېتىم تەكرارلىمايدۇ.
  • شۇ چاغدا قالدۇرۇپ قويغاننى تولۇقلايدۇ. پاراڭلاشقاندا ئەسلەتمە تاقاق بولغان، ئاجىز مودېل ساقلىمىغان ياكى كونا سۆھبەتلەرنى ئىمپورت قىلغان بولۇشىڭىز مۇمكىن. قايتا قويۇش باسقۇچى بۇ قالغان پاكىتلارنى كېيىن تولۇقلايدۇ.
بىر جۈملە بىلەن ئېيتقاندا، چۈش كۆرۈش Agent ئۇزاق مۇددەتلىك ئەسلەتمىسىنىڭ «ئاسراش جەريانى». ئۇ بولمىسا ئەسلەتمە پەقەت كۆپىيىپ، زىتلىق توپلىنىپ، ئارخىپ تارقىلىدۇ؛ Agent ئۇزاق ئىشلىتىلگەنچە قالايمىقانلىشىدۇ. ئۇ بولسا ئەسلەتمە ئىخچاملىشىدۇ، ئارخىپ توغرىلىنىدۇ، سۆھبەتلەر ئارا ئۆگىنىدۇ. شۇندىلا «ئىشلەتكەنسېرى سىزنى ياخشى چۈشىنىش» ھەققىدە سۆز قىلغىلى بولىدۇ.

قاچان ئىجرا بولىدۇ، سىز باشقۇرۇشىڭىز كېرەكمۇ؟ سۈكۈتتىكى ھالەتتە ئوچۇق، ئارقا سۇپىدا تۆۋەن چاستوتىدا ئىجرا بولۇپ كومپيۇتېرىڭىزنى دائىم ئاۋارە قىلمايدۇ. توقۇلما چىقىرىش ئېھتىمالى بار LLM بىرىكتۈرۈش باسقۇچىدا قوشۇمچە قوغداش بار: مودېلنى ئۆزىڭىز سەپلىگەندە ئاندىن ئېچىلىدۇ. سەپلىمىسىڭىز نۆل توقۇلمىلىق مېخانىكىلىق رەتلەشلا بولىدۇ، LLM ئەسلەتمىگە تەگمەيدۇ. ئۈستەل يۈزىگە خاس يەنە بىر نۇقتا: كومپيۇتېر تاقالسىمۇ قالمايدۇ؛ كېيىن ئېچىلغاندا ئاخىرقى قېتىمدىن يېتەرلىك ۋاقىت ئۆتكەن بولسا، ئاۋۋال كەم قالغان ئۇيقۇنى تولۇقلاپ، ئاندىن تۆۋەن چاستوتىدا داۋاملىشىدۇ. خالىمىسىڭىز ھەر ۋاقىت تاقىيالايسىز؛ «مودېل ئەسلەتمىنى ئۆزگەرتىش» قەدىمىنى «مودېلنى ئۆزىڭىز تەشەببۇسكارلىق بىلەن سەپلىشىڭىز كېرەك» دېگەن شەرتكە باغلىدىم، شۇڭا سۈكۈتتىكى ھالەت بىخەتەر.

قارار سىزنىڭ، بىخەتەرلىكمۇ بار

ئاسان باشقۇرۇش manage_memory.go ئارقىلىق: «قېنىق تېمىنى ياخشى كۆرىدىغانلىقىمنى ئېسىڭدە تۇت»، «بايىقىنى ئۇنتۇ»، «بۇنىڭدىن كېيىن ماڭا خەنزۇچە جاۋاب بەر» دېسىڭىز، مودېل قوشىدۇ، ئۆزگەرتىدۇ، ئۆچۈرىدۇ ياكى ئۈستىگە قويىدۇ. پاراڭدا نېمىنى ساقلاش كېرەكلىكىنىمۇ ئۆزى باھالايدۇ. ئەمما ئىككى سىزىق ئۆزگەرمەيدۇ: كىنىشكا ئەسلەتمىگە ھەرگىز كىرمەيدۇ. مەزمۇن پارول ياكى مەخپىي ئاچقۇچقا ئوخشىسا بىۋاسىتە رەت قىلىنىپ، شىفىرلانغان ئۇلىنىش مەركىزىگە يوللىنىدۇ. بارلىق يېزىش ئوخشاش يەككە يازغۇچ، تەكرارنى چىقىرىش ۋە تارىخ ساقلاش قائىدىسىدىن ئۆتىدۇ. AI ئۆزى ساقلىغان، سىز قولدا ئۆزگەرتكەن ياكى كېچىدە چۈش كۆرۈپ رەتلىگەن بولسۇن، ھېچقايسىسى بۇ قائىدىدىن ھالقىيالمايدۇ.

«تۇرۇشلۇق جاي» ئەسلەتمىسىنىڭ ئۆمرى مۇشۇ يەردە تاماملاندى: ئۇ يوشۇرۇن ئىزاھلىق بىر قۇر Markdown غا ساقلىنىدۇ، پىكىر ئۆزگەرگەندە ئۆچۈرۈلمەي كۈچتىن قالدى دەپ بەلگىلىنىدۇ، ئۈچ ئۆلچەملىك نومۇر بىلەن ئەسلىتىلىدۇ، كېچىدە ئىككى باسقۇچلۇق چۈش كۆرۈش ئارقىلىق ئارخىپقا رەتلىنىدۇ. باشتىن-ئاخىر ئۇنى cat بىلەن كۆرەلەيسىز، git diff بىلەن سېلىشتۇرالايسىز ۋە بىر جۈملە بىلەن ئۆزگەرتەلەيسىز.

ئادىل بىر گەپنىمۇ ئېيتىشىم كېرەك: ماقالە نامىدىكى «ئۇلارنىڭ چۈشى بۇلۇتتا» دېگەن سۆز تولۇق توغرا ئەمەس. Claude Code نىڭ Auto Dream مۇ يەرلىك ھۆججەتلەرنى رەتلەيدۇ. HexClaw نىڭ ھەقىقىي پەرقى ئۈچ نۇقتىنىڭ بىرلىكىدە: چۈش كۆرۈش لوگىكىسى ئوچۇق كود، ئوقۇيالايسىز؛ ھېسابلاشنى پۈتۈنلەي يەرلىكتە ئىجرا قىلغىلى بولىدۇ، Ollama ئۇلىسىڭىز ئەسلەتمىنى رەتلىگەندىمۇ باشقىلارغا يوللاش ھاجەتسىز؛ پۈتۈن جەريان ئاددىي تېكىست بولۇپ، git بىلەن كەينىگە ياندۇرغىلى بولىدۇ. ھەر بىرىنى ئايرىم ئالساق بىردىنبىر ئەمەس، بىرلەشكەندىلا پەرق چىقىدۇ. بۇ ماقالىدە HexClaw ئۈچۈن ھېچقانداق benchmark نەتىجىسى ئېلان قىلمىدىم: يۇقىرىدا تىلغا ئېلىنغان ChatGPT نىڭ 82.8% ى بىلەن Harvey نىڭ 6 ھەسسىسى ئۇلارنىڭ ئاشكارا نەتىجىسى. HexClaw ئۈچۈن پەقەت مېخانىزم بىلەن تۇراقلىق قىممەتنى كۆرسەتتىم؛ سېلىشتۇرما باھالاش قىلمىغاچقا ئەمەلىي ئۆلچەش سانىنى توقۇمىدىم.

سىز ئۇخلاۋاتقاندا، ئۇ كۈندۈزى ئېيتقان پارچە گەپلەرنى سىزنى تېخىمۇ چۈشىنىدىغان ئارخىپقا رەتلەيدۇ. بۇ «چۈش» بۇلۇتتا ئەمەس، ئۆز كومپيۇتېرىڭىزدىكى قەغەزدە، ھەر بىر قۇرىنى ۋاراقلىغىلى بولىدۇ.

بۇ ماقالە پەقەت ئەسلەتمە، يەنى ئۆزى ئۆگىنىپ، ئۆزى رەتلەيدىغان «ئىككىنچى مېڭە»نىڭ يېرىمىنى سۆزلىدى. يەنە يېرىمى سىز تەشەببۇسكارلىق بىلەن بەرگەن ماتېرىيال، ھۆججەت ۋە مەنبە كود، يەنى بىلىم ئامبىرى. بۇ ئىككىسى ئوخشاش يەرلىك ئىزدەش ئاساسىنى ئورتاق ئىشلىتىدۇ، ئەمما پۈتۈنلەي ئوخشىمايدىغان ئىككى خىل «ئەستە تۇتۇش»قا ئايلاندى: ئەسلەتمە چۈش كۆرىدۇ، بىلىم ئامبىرى كۆرمەيدۇ. بۇ كېيىنكى ماقالىنىڭ تېمىسى.
