ئۆتكەن يىلى ئۆزۈمگە بىر AI Agent ئورۇنلاشتۇرماقچى بولدۇم.

بازاردا AI Agent مەھسۇلاتلىرى ئاز ئەمەس، چوڭ شىركەتلەرمۇ ئارقا-ئارقىدىن كىرىشتى. لېكىن ئايلاندۇرۇپ باقسام، يەنىلا مۇشۇ مەسىلىلەر:

  • ئوچۇق كودلۇقلىرى بىخەتەر ئەمەس — OpenClaw (قىسقۇچپاقا) نىڭ ئىقتىدارى ئەڭ تولۇق، جامائەتچىلىكى ئەڭ چوڭ؛ لېكىن بىخەتەرلىك جەھەتتە ئاساسەن قوغدىنىشسىز، تەننەرخ كونترولىمۇ يوق، ئىشلەپچىقىرىش مۇھىتىغا قويۇشقا جۈرئەت قىلالمايمەن
  • بىخەتەرلىرى ئوچۇق كودلۇق ئەمەس — سودا مەھسۇلاتلىرى قائىدىگە ئۇيغۇنلۇقنى ياخشى قىلغان، لېكىن يېپىق كودلۇق، بۇلۇتتا ساقلىنىدۇ، سانلىق مەلۇماتنىڭ چېگرادىن چىقىشىنى كونترول قىلغىلى بولمايدۇ، ئايلىق ھەقمۇ ئەرزان ئەمەس
  • ئىشلىتىشكە بولىدىغانلىرى جۇڭگو سۇپىلىرىنى قوللىمايدۇ — Feishu، DingTalk، WeCom، WeChat ئاممىۋى ھېساباتى؛ چەت ئەل مەھسۇلاتلىرى ئاساسەن قاپلىمايدۇ

ماڭا لازىم بولغىنى: ئوچۇق كودلۇق مەھسۇلاتنىڭ ئىقتىدار كەڭلىكى + سودا مەھسۇلاتىنىڭ بىخەتەرلىك دەرىجىسى + جۇڭگو سۇپىلىرىنى تولۇق قاپلاش، شۇنىڭ بىلەن بىرگە ئۆزى باشقۇرۇپ ئورۇنلاشتۇرۇش ۋە يەككە binary بىلەن ئىجرا قىلىش. ئىزدەپ تاپالمىغاچقا، ئۆزۈم ياسىدىم. بىر كىشى + Claude بىلەن جۈپ ئىجادىيەت، ئالتە ئامبار، پۈتۈن قاتلاملىق AI Agent. بۇ دەل HexClaw (دەريا قىسقۇچپاقىسى)。

بۇ ماقالىدە تولۇق ئارخىتېكتۇرىنى ئاچىمەن: تېخنىكىلىق قارارلار، ئىجرا تەپسىلاتى ۋە يولۇققان ئورەكلەرنى ئاشكارا سۆزلەيمەن.

باشلاشتىن ئىلگىرى بىر نەچچە ئۇقۇمنى توغرىلايلى (ئاللىبۇرۇن پىششىق بولسىڭىز ئاتلاپ ئۆتسىڭىز بولىدۇ):

LLM = ھەممە كىتابنى ئوقۇغان تالانتلىق ئۇنىۋېرسىتېت ئوقۇغۇچىسى؛ ھەممىنى بىلىدۇ، لېكىن بىلىمىنىڭ ۋاقتى بار، ئاندا-ساندا توقۇيدۇ (خام خىياللىق جاۋاب)RAG = بۇ ئوقۇغۇچىغا پايدىلىنىش خاتىرىسى بېرىپ، قۇرۇق توقۇش ئورنىغا مەنبەگە تاياندۇرۇشMCP = ھەممىباب USB ماسلاشتۇرغۇچ؛ مېڭە بىلەن ھەر خىل قورالنى چېتىپلا ئىشلىتىشكە بولىدۇAgent = كۆپ ئىقتىدارلىق ئىشچى؛ ئۆزى پىلانلايدۇ، قورال چاقىرىدۇ، نەتىجە تاپشۇرىدۇSkills = ئىشچىنىڭ كەسپىي ماھارەت گۇۋاھنامىسى، ئېھتىياج بويىچە يۈكلىنىدۇ Agent گۇرۇپپىسى = بىر گۇرۇپپا ئىشچىدىن تۈزۈلگەن، ئىش تەقسىملىشىپ ھەمكارلىشىدىغان كوللېكتىپ

HexClaw قىلىدىغان ئىش، بۇ ئۇقۇملارنى قۇرۇلۇش ئارقىلىق ئەمەلىيلەشتۈرۈپ، ئىجرا بولىدىغان سىستېمىغا ئايلاندۇرۇش。

نېمىشقا Go، نېمىشقا ئۆزىمىزنىڭ رامكىسى؟

ئىككى سوئالغا بىللە جاۋاب بېرىمەن.

تىل تاللاش: Agent نىڭ توسالغۇسى I/O — LLM جاۋابىنى، قورال ئىجراسىنى، 13 سۇپىنىڭ Webhook ىنى كۈتۈش. goroutine، Python asyncio دىن بىر دەرىجە ئۈنۈملۈك، GIL مۇ يوق. ئورۇنلاشتۇرۇشتا، hexclaw serve بىر بۇيرۇق بىلەن ئىجرا قىلىنىدۇ، مەۋھۇم مۇھىت بىلەن ئاۋارە بولۇش كېرەك ئەمەس.

رامكا تاللاش: Python تەرەپتە LangChain/LangGraph (ئېكولوگىيەسى ئەڭ چوڭ، لېكىن GIL چەكلىمىسى بار)، CrewAI (باشلاش تېز، لېكىن تەشكىللەش ئاجىزراق) نى باھالىدىم؛ Go تەرەپتە Eino (ByteDance مەھسۇلاتى، لېكىن بىخەتەرلىك مودۇلى كەم) نى كۆردۈم. ئاخىرى ئۆزۈم قۇردۇم، چۈنكى Go ئەسلىي + كارخانا دەرىجىلىك بىخەتەرلىك + تولۇق RAG + ئىشلەپچىقىرىش دەرىجىلىك كۆزىتىش دېگەن بىرلەشمە تەييار نەرسە يوق ئىدى.

Python LangChain دا Agent، Tool، Chain، Retriever ئوخشىمىغان ئابستراكسىيەلەر؛ بىرلەشتۈرۈش ئۈچۈن ئۇلىغۇچى كود لازىم. Hexagon تېخىمۇ بىۋاسىتە يول تاللايدۇ: بارلىق بۆلەكلەر ئوخشاش گېنېرېك كۆرۈنمە يۈزنى ئەمەلىيلەشتۈرىدۇ، 6 خىل ئىجرا پارادىگمىسى بار (Invoke / Stream / Batch / Collect / Transform / BatchStream).

Agent باشقا بىر Agent نىڭ قورالى بولالايدۇ، RAG تۇرۇبا يولى گراف تەشكىللەش تۈگۈنىگە كىرەلەيدۇ؛ چۈنكى ئۇلار ئوخشاش كۆرۈنمە يۈزنى ئىشلىتىدۇ.

يادرولۇق پەرق بىخەتەرلىك ئۆلچىمىدە. Eino دا كۆرسەتمە قىستۇرۇشنى بايقاش، PII نى يوشۇرۇش، RBAC ۋە تەننەرخ كونترول پۈتۈنلەي بوش. دېمەك، Eino بىلەن ئىشلەتكۈچىگە يۈزلەنگەن Agent قۇرسىڭىز، بۇ ئىقتىدارلارنى نۆلدىن ئۆزىڭىز قۇرۇشىڭىز كېرەك. Hexagon ئۇلارنى رامكىنىڭ ئىچكى ئىقتىدارى قىلغان، قاچىلاپلا بار.

بىر جۈملە بىلەن: LangChain نىڭ كۆرۈنمە يۈز پىكرى + LangGraph نىڭ تەشكىللەش ئىقتىدارى + كارخانا دەرىجىلىك بىخەتەرلىك قاتلىمى، Go بىلەن قايتا يېزىلغان. سېزىش قاتلىمى (Agent) → ئىجرا قاتلىمى (Skills + MCP) → بىلىم قاتلىمى (RAG + LLM + Memory) نىڭ ئۈچىمۇ ئىچىگە قوشۇلغان.

ئون خىل Agent + كۆپ Agent ھەمكارلىقى

Agent ئاددىيدىن مۇرەككەپكە تۆت باسقۇچتا تەرەققىي قىلىدۇ؛ Hexagon، 10 خىل Agent ۋە ھەمكارلىق كېلىشىمى بىلەن ھەممىسىنى قاپلايدۇ:

باسقۇچ Hexagon نىڭ ئەمەلىيلەشتۈرۈشى تىپىك سىنارىيە
سوئال-جاۋاب BaseAgent FAQ، بىلىم سۈرۈشتۈرۈش
SOP جەريانى SequentialAgent / Process تەستىق ئېقىمى، OA
ئومۇمىي مۇستەقىللىق ReActAgent / ReflectionAgent / SelfDiscoveryAgent / PlanExecuteAgent شەخسىي ياردەمچى، ئوچۇق ۋەزىپە
كۆپ Agent ھەمكارلىقى ParallelAgent / LoopAgent / DeepAgent / SupervisorAgent يۇمشاق دېتال ئىجادىيىتى، تەتقىقات دوكلاتى

ئىچكى-سىرتقى قەۋەت قىلىش تەبىئىي قوللىنىدۇ: Supervisor نىڭ ئىشچىسى ReActAgent بولالايدۇ، ReActAgent قورالى PlanExecuteAgent نى قوزغىتالايدۇ.

ھەمكارلىق قاتلىمىدا: Team (4 ھالەت) / Handoff (Swarm ئۇسلۇبىدىكى ئالماشتۇرۇش) / Network (Mesh/Hub/Ring/Tree توپولوگىيەسى) / Consensus (بېلەت تاشلاپ قارار قىلىش) / Registry (مۇلازىمەت بايقاش + يۈك تەڭپۇڭلاشتۇرۇش) / A2A (Google نىڭ Agent-to-Agent كېلىشىمى، Go ئېكولوگىيەسىدە ئاز ئۇچرايدۇ). تۆت قاتلاملىق ھالەت باشقۇرۇش + Snapshot/Restore.

ReAct ماتورى

ماتور، Hexagon ReActAgent نىڭ ئۈستىگە ئەپ قاتلىمى تەشكىللەشنى قوشىدۇ (يەككە ھۆججەت 47KB):

LoadContext → InjectContext(RAG+Memory) → InjectTools(Skill+MCP, limit 40)

→ AutoMemory → SaveHistory → Response

3D ئاتوملۇق خامچوت: ئۈچ atomic.Int64 ئارقىلىق Token، ۋاقىت ۋە تەننەرخ ئايرىم ئىزلىنىدۇ. نېمىشقا تەننەرخكە float64 ئىشلەتمەيمىز؟ Go نىڭ atomic بوغچىسى لەيلىمە سان ئاتوم مەشغۇلاتىنى قوللىمايدۇ، Agent نىڭ قورال چاقىرىشىدا بولسا پاراللېللىق يۇقىرى. ھەل قىلىش چارىسى دوللارنى بىر مىليونغا كۆپەيتىپ پۈتۈن سان ساقلاش (مىكرو دوللار ئېنىقلىقى): $0.00004 بولسا 40 كە ئايلىنىدۇ. پۈتۈن سان ئاتوم مەشغۇلاتى، قۇلۇپ خىراجىتى نۆل. 20+ مودېل باھا جەدۋىلى بار، تارماق Agent خامچوتىنى تەقسىملەش ۋە قايتۇرۇۋېلىشنى قوللايدۇ.

Two-Pass Streaming: ئارىلىق نۆۋەتتە Complete() (tool_calls نى بايقاش)، ئاخىرقى نۆۋەتتە Stream() (خەت يېزىش ئۈنۈمى). كۆرۈنمەيدىغان قەدەملەرگە ئېقىم ئۇلىنىشى قۇرۇشتىن ساقلىنىدۇ. ئېقىم goroutine ى ئايرىم context.Background() بىلەن ئۇچۇر ساقلايدۇ، ئىشلەتكۈچى بەتنى تاقىغاندا سانلىق مەلۇمات يوقاپ كېتىشنىڭ ئالدىنى ئالىدۇ.

Hook Chain: TruncateHook بېشىنىڭ 60% ى + ئاخىرىنىڭ 20% ىنى قالدۇرىدۇ · SanitizeHook پەقەت سىرتقى مەنبەنى تازىلايدۇ · AuditHook مەغلۇپ بولغاندىمۇ ئىجرا بولىدۇ. قورال cache ى SHA256 key ئىشلىتىدۇ، بۇزغۇنچىلىق خاراكتېرلىك قوراللار ئاپتوماتىك ئاتلىنىدۇ.

Skill ئېكولوگىيەسى (ClawHub): 37 Skill + 38 MCP Server. فورماتى Markdown + YAML frontmatter؛ مەنبەسى 18 ئۆز ئىجادىيىتى + 12 جامائەتچىلىكتىن ماسلاشتۇرۇلغان + 7 OpenClaw playbook كۆچۈرۈلمىسى. MCP، 18 تۈرنى قاپلايدۇ (ھۆججەت سىستېمىسى / GitHub / ئىزدەش / توركۆرگۈچ / ساندان / Slack / Docker / K8s / AWS قاتارلىقلار).

Go نىڭ ئۈچ سۇپىلىق ئەسلىي sandbox ى: 2713 قۇر بىلەن Docker نىڭ ئورنىنى ئېلىش

OpenClaw قاتارلىق رىقابەتچىلەرنىڭ كۆپىنچىسى كود ئىجرا قىلىشتا Docker غا تايىنىدۇ. hexclaw، 2713 قۇر ساپ Go بىلەن يادرو دەرىجىلىك ئايرىشنى ئەمەلىيلەشتۈرىدۇ:

macOS Seatbelt (Claude Code / Codex بىلەن ئوخشاش تۆۋەنكى تېخنىكا) — ھەرىكەتچان SBPL سىياسىتى، (deny default) سۈكۈتتە رەت قىلىنىدۇ. Docker قاچىسى سۈكۈتتە كۆپىنچە syscall ئىجازەتلىرىگە ئىگە، بۇنى قىلالمايدۇ.

Windows نىڭ بەش قاتلاملىق چوڭقۇر مۇداپىئەسى — ① Restricted Token (UNTRUSTED_RID 0x0000) → ② ACL ھۆججەت سىستېمىسى ئايرىشى → ③ Job Object (512MB / 10 جەريان) → ④ Low Box Token يادرو دەرىجىلىك تور ئۈزۈش → ⑤ Alternate Desktop (Shatter Attack تىن ساقلىنىش). قوزغىلىش تەخمىنەن 50ms / 5MB؛ Docker Desktop بولسا 500ms-2s.

يولۇققان ئورەكلەر ۋە ئارخىتېكتۇرا تاللاشلىرى

1-ئورەك: Docker sandbox — «پاراڭ ياردەمچىسى ئۈچۈن يەنە Docker قاچىلامدىم؟»

دەسلەپ Skill ئىجراسى Docker غا تايىناتتى. ئادەتتىكى MacBook سەپلىمىسىدە مەسىلە يوق، لېكىن macOS تا Docker Desktop قوشۇمچە 2-4GB ئىچكى ساقلىغۇچ يەيتتى؛ ئىشلەتكۈچى ھاۋارايى سۈرۈشتۈرۈش ئۈچۈن Docker قاچىلىشى مۇۋاپىق ئەمەس.

بىر ھەپتە ۋاقىت سەرپ قىلىپ، Go syscall ئارقىلىق ئۈچ سۇپىلىق ئەسلىي sandbox نى قايتا يازدىم: 2713 قۇر، نۆل تايىنىشچانلىق، <10ms قوزغىلىش. ئايرىش كۈچى تولۇق قاچىدەك ئەمەس، لېكىن Skill ئىجرا سىنارىيەسىگە يېتەرلىك.

2-ئورەك: Wails → Tauri — خاتا تاللاشتىن توغرا بۇرۇلۇش

ئۈستەل يۈزى ئۈچۈن دەسلەپ Wails تاللانغان. سەۋەبى يېتەرلىك: Go ئەسلىي، بىرلەشتۈرۈش تەننەرخى نۆل. 60% ئىجاد قىلىنغاندا ئۈچ ئېغىر مەسىلە بايقالدى: كۆپ كۆزنەك يوق (Quick Chat لەيلىمە كۆزنىكىنى قىلغىلى بولمايدۇ)، سىستېما تەخسىسىگە ئۈچىنچى تەرەپ كۈتۈپخانىسى لازىم، ئاپتوماتىك يېڭىلاش يوق.

زىياننى توختىتىپ Tauri v2 گە ئۆتتۈم. Go ئارقا تەرىپى Sidecar غا ئايلاندى، بىر HTTP قاتلىمى كۆپەيدى؛ لېكىن مەۋجۇت 71 API نى دەل قايتا ئىشلەتكىلى بولغاچقا، ئەمەلىي ئىجاد تەننەرخى تېخىمۇ تۆۋەن بولدى.

3-ئورەك: بىخەتەرلىك دەرۋازىسى ئەسلىدە «ئىختىيارىي سەپلىمە» ئىدى

بىرىنچى نەشرىدە بىخەتەرلىك قاتلىمى middleware قىلىنغان؛ سەپلىمە ھۆججىتىدە enabled: false دېيىلسە ئۆچۈرگىلى بولاتتى. بىر code review دا، CostCheck ئۆچسە كونترولدىن چىققان ReAct ھالقىسى پۇل ھېساباتى پارتلىغۇچە LLM نى چەكسىز چاقىرىدىغانلىقى بايقالدى. بۇ نەزەرىيەۋى خەۋپ ئەمەس، ئېنىق ئاپەت ئىدى.

شۇ كۈنى ئۇنى ئايلىنىپ ئۆتكىلى بولمايدىغان 6 قاتلاملىق تۇرۇبا يولىغا قايتا قۇردۇم. ئىجاد مەزگىلىدە چاستوتا چەكلىمىسى كۆپ قوزغىلىدۇ، لېكىن يېرىم كېچىدە API پۇل ھېساباتى كەلگەندىن ياخشى.

كېيىن نېمە قىلىمىز؟

2026-يىلى AI Agent ساھەسى «تېخنىكا دەلىللەش»تىن «قۇرۇلۇش ئارقىلىق ئەمەلىيلەشتۈرۈش»كە كىردى: MCP + A2A قوش كېلىشىم قاتلىمى پىشىپ، بىخەتەرلىك ۋە بەلگىلىك ھەرىكەت «Demo ئىجرا بولسىلا بولدى» دېگەن قاراشنىڭ ئورنىنى ئالدى. HexClaw ھازىر v0.2.x، يادرولۇق ئىقتىدارى مۇقىم، لېكىن «ئىشلەپچىقىرىش دەرىجىسى»گىچە مۇھىم كەمچىلىكلەر بار:

  • ئېقىم يېڭىلىشى: ھازىر ساختا ئېقىم (ئارىلىق نۆۋەتلەر ماس قەدەملىك)، Hexagon Agent نىڭ ئەسلىي Stream ئىقتىدارىغا ئۇلاش پىلاندا
  • Embedding بىرلەشتۈرۈش: بىلىم ئامبىرىنىڭ Embedder كۆرۈنمە يۈزى بەلگىلەنگەن، LLM Provider غا ئۇلاش لازىم
  • سىناق قاپلىشى > 80%: 93 سىناق ھۆججىتى بار، قاپلاش نىسبىتىنى ئۆستۈرۈش كېرەك
  • Hub ئېكولوگىيەسىنى كېڭەيتىش: 37 Skill → 100+، 38 MCP Server → 80+؛ كود تەكشۈرۈش / سانلىق مەلۇمات تەھلىلى / تۈر باشقۇرۇشنى تولۇقلاش
  • كۆپ سۇپىلىق ئۈستەل يۈزىنى ياخشىلاش: Mac ئالدىنقى، Windows MSI ۋە Linux AppImage غا تېخىمۇ كۆپ سىناق لازىم

ئوچۇق بىر سوئال: بىخەتەرلىكتىن ۋاز كەچمەي Agent نى قانداق تېخىمۇ مۇستەقىل قىلىمىز؟ Tool Approval بىخەتەرلىكنى كاپالەتلەندۈرىدۇ، لېكىن مۇستەقىللىقنى چەكلەيدۇ؛ تارىخىي ھەرىكەتكە ئاساسلانغان ئۆزلىشىشچان تەستىق سىياسىتى ئۈستىدە ئىزدىنىۋاتىمىز. بۇمۇ AI Agent ساھەسىنىڭ 2026-يىلدىكى يادرولۇق زىددىيىتى: «Demo ئىجرا بولۇش»تىن «ئىشلەپچىقىرىشتا ئىشەنچلىك بولۇش»قا ئۆتۈشتە، بىخەتەرلىك بىلەن مۇستەقىللىقنىڭ تەڭپۇڭ نۇقتىسى قەيەردە؟
