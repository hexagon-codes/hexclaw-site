HexClaw vs OpenClaw / Hermes: 2026-يىلى يەرلىك AI Agent نىڭ ئۈچ يولى

راكنى، ئاتنى ياكى قىسقۇچپاقىنى بېقىش: ئۈچ يول ئۈچ مەسىلىنى ھەل قىلىدۇ. ئىقتىدار تىزىملىكى ئوخشىشىپ كەتسىمۇ، مەھسۇلات يولى باشقا. ئۈسكۈنە تەرەپ AI تېز كېڭىيىۋاتقاندا، ھەر بىرىنىڭ قۇرۇلما تاللىشى نەگە بارىدۇ؟

تۇنجى قېتىم WeChat رەسمىي ھېساباتىدا ئېلان قىلىنغان بۇ ماقالە ئالدى بىلەن WeChat رەسمىي ھېساباتى「hexclaw」(ID: hexclaw) نىڭ رەسمىي تېخنىكا سەھىپىسىدە ئېلان قىلىنغان · ئېلان ۋاقتى: 2026-يىلى 4-ئاينىڭ 25-كۈنى · ئوقۇشقا تەخمىنەن 12 مىنۇت
WeChat دىكى ئەسلى ماقالە ↗

ئۆتكەن يىلدىن بۇ يىلغىچە AI ساھەسىدىكى ئەڭ ئەستە قالغان ھايۋان بىر راك بولدى.

OpenClaw ئەسلى پەقەت پاراڭ كۆزنىكىدە جاۋاب بېرەلەيدىغان AI نى كۈندىلىك خىزمەت ئېقىمىڭىزدا ياشايدىغان «رەقەملىك خىزمەتداش»قا ئايلاندۇردى. «راك باقتىڭىزمۇ؟» بىر مەزگىل دوستلار چەمبىرىكى ۋە ئاچقۇچىلار توپىدىكى سالامغا ئايلاندى.

ئەمما يېقىندا بۇ ساھەنى كۆزىتىپ تۇرغان بولسىڭىز، كىشىلەر سۆزلەۋاتقان ھايۋاننىڭ ئاستا ئالماشقىنىنى بايقايسىز.

جامائەتتىكى بىر مودا سۆز بۇنى جانلىق ئىپادىلەيدۇ:كىرىمنىي ۋادىسى راك بېقىشنى قويۇپ، ئات بېقىشقا باشلىدى(Hermes نىڭ خەنزۇچە نامى «爱马仕» دا «马» — ئات دېگەن خەت بار). بۇ چاقچاق پەقەت ئاھاڭداشلىق ئۈچۈن تارقالمىدى: GitHub يۇلتۇزلىرى ۋە OpenRouter چاقىرىش مىقدارى دېگەن ئىككى ئوچۇق كۆرسەتكۈچ ھەقىقەتەن ئۆرلەۋاتىدۇ.

شۇڭا بۇ قېتىم ئىنژېنېرلىق تاللاش نۇقتىسىدىن«راك بىلەن Hermes» نى «ئۈچىنچى يول»غا كېڭەيتىپ، ئۈچ مەھسۇلاتنىڭ ھەر بىرى قايسى لايىھە مەسىلىسىنى ھەل قىلىدىغانلىقىنى سۆزلەيمىز.

بىرىنچى ماقالە«راك بېقىشتىن قىسقۇچپاقا بېقىشقىچە»«نېمىشقا HexClaw نى ياساش كېرەك»كە جاۋاب بەرگەن بولسا، بۇ ماقالە كېيىنكى سوئالغا جاۋاب بېرىدۇ: OpenClaw بىلەن Hermes ئالغا ماڭغاندا HexClaw قايسى قەۋەتتە تۇرىدۇ؟

ماقالىنىڭ ئاساسلىق قارىشى
OpenClaw، Hermes ۋە HexClaw ئەمەلىيەتتەئوخشاش قەۋەتتە ئەمەس— بىرى كىرىش ۋە تارقىتىشقا، بىرى تونۇش ۋە ئۆزلۈكىدىن ئۆگىنىشكە، بىرى يەرلىك خىزمەت ئۈستىلىگە مەسئۇل.
بۇ ماقالە كىمنىڭ كۈچلۈكلىكىنى ئىسپاتلاش ئۈچۈن ئەمەس، ئۈچ يولنى بىر قۇرۇلما رەسىمىدە ئېنىق كۆرسىتىش ئۈچۈن.
بىر جۈملىلىك تاللاش:
كۆپ سۇپا IM / Bot ماترىتساسى ئۈچۈن ئالدى بىلەن OpenClaw。
ئۆزلۈكىدىن ئۆگىنىدىغان Agent / ئۇزۇن ۋەزىپە پىلانلاش ئۈچۈن ئالدى بىلەن Hermes。
ئورۇنلاشتۇرۇش بىلەن ئاۋارە بولمايدىغان، سانلىق مەلۇماتى يەرلىكتە قالىدىغان ئۈستەل يۈزى خىزمەت مۇھىتى ئۈچۈن ئالدى بىلەن HexClaw。

Hermes نېمىشقا مودا بولدى؟

ئالدى بىلەن Hermes (Hermes Agent) نى چۈشىنىۋالايلى. قىسقا ۋاقىتتا ئاچقۇچىلار مۇنازىرىسىنىڭ مەركىزىگە كىرگەن ئىكەن، كەم دېگەندە ئېنىق بىر سېتىش نۇقتىسىنى تۇتقان.

سانلىق مەلۇمات جەھەتتە Hermes كۆزگە كۆرۈنگەن ئوچۇق مەنبە تۈر:

  • 2026-يىلى 2–3-ئايلار ئارىسىدا Nous Research جىمجىت ئوچۇق مەنبە قىلغان
  • 2026-04-25 گىچە GitHub يۇلتۇزى تەخمىنەن 116k، Fork تەخمىنەن 17k（github.com/NousResearch/hermes-agent）
  • OpenRouter ئەپ بېتىدىكى مىقدار تەخمىنەن 4.4T Total tokens، دۇنيا كۈندىلىك رەت تەرتىپىدە 3（openrouter.ai/apps/hermes-agent）
  • WeChat نى بىۋاسىتە قوللايدۇ، iLink Bot API ئارقىلىق QR كود سىكاننېرلاپلا ئىشلىتىلىدۇ

تالاش-تارتىش ئىزاھى: Hermes Agent بىلەن EvoMap / Evolver ئوتتۇرىسىدا يېقىندا ئوخشاشلىق تالاش-تارتىشى بار. بۇ ماقالە ئۇنىڭغا ھۆكۈم چىقارمايدۇ؛ پەقەت ئوچۇق ئامبار، ھۆججەت ۋە مەھسۇلات شەكلى ئاساسىدا ئىنژېنېرلىق تاللاشنى سۆزلەيدۇ. ئالاقىدار ماتېرىياللار ئاخىرىدا.

ئۇنىڭ تارقىلىشىنى ئىلگىرى سۈرگىنى پەقەت سانلار ئەمەس، بەلكى «يېزىشقا بولىدىغان ئىجرا مۇھىتى» (Writable Runtime) دېگەن ئۆزلۈكىدىن ئۆگىنىدىغان Agent ھېكايىسىنى ئالدىنقى سەپكە چىقارغانلىقى.

قايتا-قايتا نەقىل قىلىنىدىغان بىر ئىپادە شۇ:

ئىلگىرى OpenClaw مۇقىم ئىجراچىغا يېقىن ئىدى: ئېقىمنى ئېنىق يازسىڭىز داۋاملىق ئىجرا قىلىدۇ؛ مەسىلەئۇنىڭ «ئەستە قالدۇرماسلىقى»، بىر قېتىم مۇرەككەپ ۋەزىپە پۈتسىمۇ، كېيىن يەنە باشتىن باشلايدۇ.
Hermes باشقا يول ئالدى: ۋەزىپە پۈتسە ئۆزلۈكىدىن قايتا تەھلىل قىلىپ، تەجرىبىنى قايتا ئىشلىتىلىدىغان Skill ھۆججىتىگە ئايلاندۇرىدۇ؛ ئوخشىشى كېلىپ قالسا بۇ «تەجرىبە بوغچىسى»نى بىۋاسىتە چاقىرىدۇ.

ئاددىي ئېيتساق، Agent ساھەسىدىكى ھەممە ئىككى يىلدىن بۇيان ئويلاپ كەلگەن «قانچە كۆپ ئىشلەتسە شۇنچە ئەقىللىق» دېگەن سۆز Hermes تا ئېنىق مەھسۇلات سېتىش نۇقتىسىغا ئورالدى.

بۇنىڭغا WeChat تا QR سىكاننېرلاپلا ئىشلىتىش كىرىشى قوشۇلغاندا، خەنزۇچە تېخنىكا چەمبىرىكىدە مۇنازىرە قىزىشى ئەجەبلىنەرلىك ئەمەس.

OpenClaw ئالماشتۇرۇلمىدى، ئىش تەقسىماتى ئېنىقلاشتى

قىزىقى، ئىنژېنېرلىق قەۋەتلەش نۇقتىسىدىن Hermes OpenClaw نى «يوقاتمىدى».

بۇ ئىككى ھايۋان بىر خىل ئىش قىلمايدۇ.

  • OpenClaw نىڭ كۈچلۈك يېرى AI نى بار بولغان پاراڭ كىرىشىگە مۇقىم ئۇلاش: يىگىرمىدىن ئارتۇق سۇپا، يۈزدىن ئارتۇق قىستۇرما، كۆپ ھېسابات ماترىتساسىنى باشقۇرۇش. Discord جامائىتى باشقۇرغۇچىسى، جامائەت تىجارەتچىسى، مەشغۇلات / DevOps ياكى كارخانا IT خادىمى بولسىڭىز، ئادەتتە ئالدى بىلەن OpenClaw نى ئويلىشىسىز.
  • Hermes نىڭ كۈچلۈك يېرى بىر Agent نى داۋاملىق ئىشلىتىش جەريانىدا كۈچەيتىش: كود يېزىش، سانلىق مەلۇمات تەھلىلى، مەخسۇس ساھە تەجرىبىسىنى توپلاش. ئۇ ئۇزۇن ۋەزىپىنىڭ پىلانلاش، ئىجرا ۋە قايتا تەھلىل مەركىزىگە يېقىن.

كۆپ ئۇچرايدىغان ئىنژېنېرلىق بىرلەشتۈرۈش ئويى:Hermes پىلانلاش ۋە ئۆگىنىشكە، OpenClaw كۆپ كىرىشكە تارقىتىشقا مەسئۇل بولسۇن.

مەن بۇ قاراشقا قوشۇلىمەن. ئەمما يەنە بىر سۆز قوشاي:بۇ بىرلەشمىگە ئىقتىدارنى يەرلىك خىزمەت ئېقىمىغا چۈشۈرىدىغان خىزمەت ئۈستىلى كەم。

بىز بولساق قىسقۇچپاقا بېقىۋاتىمىز

HexClaw نى بىلىدىغان كونا ئوقۇرمەن كېيىنكى بۆلەككە ئاتلىسا بولىدۇ. تۇنجى قېتىم ئاڭلىغانلارغا قىسقىچە تونۇشتۇراي.

HexClaw AI ھەقىقىي ئىجرا بولۇۋاتقان ئوچۇق مەنبە AI Agent stack ى؛ ئۇ مەن ئالدىنقى 《Claude Code SOP》 ماقالىسىدىكىلايىھە يېتەكچىلىكى × سىناقنى تاماملاش × كۆپ Agent ھەمكارلىقىئۇسۇلى بىلەن سىلىقلىغان ئىنژېنېرلىق مىسالى. ئالدىنقى ماقالىلەر ئورنىتىش، ئىشلىتىش ۋە قۇرۇلمىنى سۆزلىگەن؛ بۇ يەردە OpenClaw / Hermes ساھەسىدە قايسى قەۋەتنى ئىگىلەيدىغانلىقىنى سۆزلەيمىز. تۈر Apache-2 ئوچۇق مەنبە، يەرلىك ئورۇنلاشتۇرۇلىدۇ، سانلىق مەلۇمات شەخسىي.

«كەلگۈسىنى ھازىرقىدەك سېتىش»تىن ساقلىنىش ئۈچۈن ئىقتىدار چېكىنى ئالدى بىلەن ئېنىقلايلى:

  • v0.3.12 دا ئېلان قىلىنغان مۇقىم ئىقتىدارلار: پاراڭ، يەرلىك MCP، Markdown Skill، RAG بىلىم ئامبىرى، كۆپ Agent، IM قاناللىرى (ئارقا تەرەپ ئېكولوگىيەسى Slack قاتارلىق تېخىمۇ كۆپ ماسلاشتۇرغۇچنى قوللايدۇ؛ ئۈستەل يۈزى ھازىر Feishu / DingTalk / WeCom / WeChat / Discord / Telegram غا مەركەزلەشكەن)، ئاۋاز، رەسىم / سىن ھاسىل قىلىش
  • v0.4.x يول خەرىتىسى (يەرلىك دەلىللەش / كېيىنكى نۇسخا نىشانى): Skill نىڭ يېپىق ئۆزلۈكىدىن ئۆگىنىشى، Agent ئىستراتېگىيە ھالىتىنى يوللاش، ئەستە ساقلاشقا يوليورۇق كىرگۈزۈشتىن مۇداپىئە، خاتالىق تۈرلەش ۋە دەرىجە تۆۋەنلىتىش، مودېلنىڭ قورال چاقىرىش ئىقتىدارىنى بايقاش، MCP ئىجرا ۋاقتى باشقۇرۇشى — تۆۋەندە ئېنىق چۈشەندۈرۈلىدۇ

ئۇنىڭ يولى قالغان ئىككىسىدىن پەرقلىق.

OpenClaw Node.js stack ىدا، Docker / Fly.io / Render ئارقىلىق ئورۇنلاشتۇرۇلىدۇ، Bot تىجارەتچىلىرىگە قارىتىلغان. Hermes Python stack ىدا، ئەمما رەسمىي تەرەپ بىر چېكىشلىك ئورنىتىش قىلىپ تەييارلىغان (Linux / macOS / WSL2 / Android Termux ئۈچۈن script بار، ئىشلەتكۈچى Python مۇھىتىنى ئۆزى تەييارلىمايدۇ). gateway / server / container ئىجرا قىلىشقا رازى تېخنىكىلىق ئىشلەتكۈچىگە تېخىمۇ ماس. ئىككىسىمۇ «مۇلازىمەت ئورۇنلاشتۇرۇش» يولىدا.

HexClaw بىرىنچى كۈندىن باشقا نەرسىگە تاياندى —AI Agent نى ئادەتتىكى ئۈستەل يۈزى يۇمشاق دېتالى قىلىش: تور كۆرگۈچ، WeChat، WPS نى ئاچقاندەك سىنبەلگىنى بىر چېكىپ ئىشقا كىرىش. شۇنىڭ ئۈچۈن Go + Tauri تاللاندى، DMG / MSI / AppImage نى ئايرىم ئورنىتىسىز؛ Docker، مەۋھۇم مۇھىت ياكى systemd كېرەك ئەمەس.

سېلىشتۇرساق ئۈچ يولنىڭ پەرقى روشەن:

OpenClaw نىڭ كۈچلۈك يېرىAI نى IM ئېقىمىڭىزغا كىرگۈزۈش。
Hermes نىڭ كۈچلۈك يېرىبىر Agent نى كۆپ ئىشلەتكەنسېرى ئۆزلۈكىدىن كۈچەيتىش。
HexClaw نىڭ نىشانىبۇلارنى مەشغۇلات باشقۇرۇشنى بىلمەي تۇرۇپلا ئىجرا بولىدىغان يەرلىك خىزمەت ئۈستىلىگە قاچىلاش。

سىرتقا تونۇشتۇرغاندا يادرولۇق ماتورنى Hexagon Agentدەپ ئاتايمەن، ئامبار نامى يەنىلا hexagon. ئاستىدا toolkit → ai-core → hexagon → hexclaw → hexclaw-desktop / hexagon-ui دېگەن ئالتە ئامبارلىق قەۋەت بار: ئالدىنقى تۆت قەۋەت Go ئامبىرى، ئايرىم نۇسخىلىنىدۇ ۋە ئايرىم go getقىلىنىدۇ؛ ئۈستەل يۈزى ۋە كۆزىتىش UI سى ئايرىم قۇرۇلۇپ ئېلان قىلىنىدۇ. تەپسىلاتى ئىلگىرى«قۇرۇلما تەپسىلىي چۈشەندۈرۈشى»دەيېزىلغان، بۇ يەردە يېيىپ ئېيتمايمىز.

ئۈچ يول ئۆز يولىدا

قاتتىق ئېيتساق، بۇ ئۈچى بىر يەرنى تالىشىۋاتمايدۇ؛ سىستېما قەۋىتىدە ھەر بىرى بىر قەۋەتنى ئىگىلەيدۇ:

OpenClaw = كىرىش قەۋىتى / تارقىتىش قەۋىتى
Hermes = تونۇش قەۋىتى / ئۆزلۈكىدىن ئۆگىنىش قەۋىتى
HexClaw = يەرلىك خىزمەت ئۈستىلى / شەخسىي سانلىق مەلۇمات ئاساسى
——ئۈچ قەۋەتلىك stack نىڭ ھەممىسىنى ھېچقايسىسى تولۇق ئىگىلىمەيدۇ؛ تاللاش قايسى قەۋەت مەسىلىسىنى ھەل قىلىشىڭىزغا باغلىق.

بۇنى چۈشەنسىڭىز، نۇرغۇن ئىككىلىنىش يوقىلىدۇ —ئۇلار stack نىڭ ئوخشىمىغان ئورنىدىكى مەسىلىنى ھەل قىلىدۇ، بىر-بىرىنى ئالماشتۇرمايدۇ. تۆۋەندە يېيىپ چۈشەندۈرىمىز.

چوڭ جەدۋەلنى ئوقۇغۇڭىز كەلمىسە: 30 سېكۇنتلۇق نۇسخا

  • OpenClaw: TypeScript / Node.js stack ى. «AI نى بار بولغان IM كىرىشىگە كىرگۈزۈش»كە ماھىر؛ كۆپ سۇپا، كۆپ ھېسابات، ماترىتسا تىجارىتى ئۇنىڭ مەيدانى.
  • Hermes: Python stack ى، ئەمما بىر چېكىشلىك ئورنىتىشقا ئورالغان. «بىر Agent نى ئىشلىتىش جەريانىدا بارغانسېرى توغرىلاش»قا ماھىر؛ Writable Runtime يادرولۇق سېتىش نۇقتىسى.
  • HexClaw: Go + Tauri stack ى، Sidecar قۇرۇلمىسى، DMG / MSI / AppImage نى قوش چېكىپ ئورنىتىسىز. «يەرلىكتە دائىم تۇرۇش، مەشغۇلات باشقۇرۇشنى بىلمەسلىك، سانلىق مەلۇماتنى يەرلىكتە ساقلاش»قا ماھىر، ئۈستەل يۈزى خىزمەت مۇھىتى شەكلىدە.

تېلېفوندا ئوقۇغۇچىلارغا يۇقىرىدىكى 30 سېكۇنتلۇق نۇسخا يېتەرلىك. چوڭقۇر سېلىشتۇرماقچى بولغانلارغا تۆۋەندە ئۈچ يولنى ئايرىپ تولۇق پايدىلىنىش ماتېرىيالى بېرىمىز.

ئىنژېنېرلىق بەدىلى: ئېكولوگىيە كۆلىمى تېخى دەسلەپكى باسقۇچتا، Skill سانى تەرەققىي قىلدۇرۇلۇۋاتىدۇ

ئىزاھ: «IM سۇپا دائىرىسى»، «كېڭەيتىش ئېكولوگىيەسى» قاتارلىقلار ھەر تۈرنىڭ رەسمىي ھۆججىتى ۋە ھازىرقى ئامبارىغا قاراپ تەخمىنەن تۈرلەندى، قاتتىق benchmark ئەمەس. «سۇپا»، «Provider»، «قورال مودۇلى» ئۆلچەملىرى بىۋاسىتە سېلىشتۇرغىلى بولمايدۇ؛ ئوقۇرمەن ئەمەلىي ئېھتىياجىغا قاراپ پايدىلانسۇن.

يۇقىرىدىكى ئۈچ بۆلەكنى ئاددىي بىر گەپكە يىغساق:

ئەگەركۆپ ھېسابات، كۆپ سۇپىنى باشقۇرۇپ نۇرغۇن كىشىگە ئۇچۇر ئەۋەتمەكچى بولسىڭىز، OpenClaw نى تاللاڭ.
ئەگەربىر Agent نىڭ ئېقىمىڭىز ۋە مايىللىقىڭىزغا ئاستا ماسلىشىشىنى خالىسىڭىز، Hermes نى تاللاڭ.
ئەگەرئۆز ماشىنىڭىزدا مەشغۇلات باشقۇرۇشنى بىلمەي ئىشلەيدىغان، سانلىق مەلۇماتنى يەرلىكتە ساقلايدىغان خىزمەت ئۈستىلى بولسۇن دېسىڭىز، HexClaw نى تاللاڭ.

ئۈچ يول توقۇنۇشمايدۇ، ئالماشتۇرۇش مۇناسىۋىتىمۇ يوق. شۇڭا كېيىنكى بۆلەكتە نەزەرىيە جەھەتتىن قانداق بىرلەشتۈرگىلى بولىدىغانلىقىنى ئايرىم سۆزلەيمىز.

OpenClaw بىلەن Hermes تا ئايرىم چۇۋۇپ ئۆگىنىشكە ئەرزىيدىغان بىر نەرسە

«قايسىسى مودا، قايسىسى كۈچلۈك» رەت تەرتىپىنى قويۇپ تۇرساق، OpenClaw ۋە Hermes تا ئەڭ ئۆگىنىشكە ئەرزىيدىغىنى ئىككى تۈپ لايىھە ئىدىيەسى؛ Agent ياسىغۇچىلار بۇنىڭدىن قېچىپ قۇتۇلالمايدۇ.

OpenClaw: «ئىقتىدار پەرقى»نى بايان قىلىش

Feishu، Discord، Slack، Telegram، WhatsApp، Matrix — ھەر IM سۇپىسىنىڭ مىجەزى باشقا: مول تېكىستلىك كۇنۇپكا ئەۋەتەلەمدۇ، ئەۋەتىلگەن ئۇچۇرنى ئۆزگەرتەلەمدۇ، بىر ئۇچۇرنىڭ خەت چېكى قانچە، thread قوللامدۇ، كارتا كېلىشىمى قانداق. ئىلگىرى ھەر ماسلاشتۇرغۇچ ئۆز شاخلىرىنى يازاتتى، Agent چاقىرغۇچى «قايسى سۇپىدىمەن، نېمە قىلالايمەن»نى ئۆزى بەلگىلەيتتى.

OpenClaw نىڭ قىلغىنى —بۇ پەرقلەرنىڭ ھەممىسىنى بايانلىق «Capabilities»كە كۆتۈرۈش. Adapter ئۆزى نېمە قىلالايدىغانلىقى ۋە قىلالمايدىغانلىقىنى ئېلان قىلىدۇ؛ ماتور بۇ بايانغا ئاساسەن دەرىجە تۆۋەنلىتىش ئىستراتېگىيەسى، كۆرسىتىش ئۇسۇلى ۋە ئۇزۇنلۇقنى بەلگىلەيدۇ. Agent قەيەردىلىكىگە كۆڭۈل بۆلمەي، ئۆز ئىشىنى قىلىدۇ.

بۇ ئابستراكسىيە ناھايىتى پاكىز. ئۇنىڭ ئارقىسىدا «كۆپ سۇپا قوللاش»تىنمۇ چوڭقۇر قاراش بار:كۆپ سۇپىلىق Agent نىڭ ئىنژېنېرلىق قىيىنچىلىقى «ئۇلاش» ئەمەس، «ئىقتىدار ماسلاشتۇرۇش». بۇنى چۈشەنسەك، OpenClaw نىڭ يىگىرمىدىن ئارتۇق سۇپىدا نېمىشقا مۇقىم ئىشلەيدىغانلىقىنى بىلىمىز: كودى كۆپ بولغانلىقتىن ئەمەس، ئابستراكسىيە قەۋىتى مۇرەككەپلىكنى Agent سىرتىدا توسقانلىقتىن.

Hermes: Skill نى «ئۆسىدىغان مۈلۈك» قىلىش

«Agent قانچە كۆپ ئىشلەتسە شۇنچە ئەقىللىق بولسۇن» دېگەن سۆز ئىككى يىلدىن بۇيان ئېيتىلىۋاتىدۇ. Hermes نىڭ مۇنازىرە قىلىشقا ئەرزىيدىغان يېرى ئۇنى يېتەرلىك ئېنىق مەھسۇلات ئايلىنىشىغا ئايلاندۇرغانلىقى.

ئۇنىڭ ئويى بىر جۈملىدە: Skill بىر يېزىپ مۇزلىتىدىغان تەڭشەك ئەمەس،داۋاملىق يېڭىلىنىدىغان ئىنژېنېرلىق مۈلكى. Agent ۋەزىپە جەريانىدا Skill نىڭ يېتەرلىك ئەمەسلىكىنى بايقىسا، ئۆزى ياماق چىقىرىپ ئىقتىدار ئامبىرىغا قايتا يازىدۇ؛ كېيىن ئوخشىشىدا بىۋاسىتە قايتا ئىشلىتىدۇ. بۇ ئايلىنىش يۈرگەندە پۈتۈن Agent «تۇراقلىق تەڭشەك»تىن «داۋاملىق يېڭىلىنىدىغان ئىقتىدار ئامبىرى»غا ئايلىنىدۇ.

تېخنىكىلىق مېخانىزمى ئۇنچە مۇرەككەپ ئەمەس: باھالاش، ئايرىپ چىقىرىش، قايتا يېزىش — ئۈچ قەدەم. قىيىنى «Agent ئۆزىنى ئۆزگەرتىدۇ»نى ھەقىقىي تۈرگە كىرگۈزۈپ، نۇرغۇن ئاچقۇچىنىڭ قولىغا بېرىشكە جۈرئەت قىلىش. «ھەممە بىلىدۇ»دىن «كەڭ كۆلەمدە مۇنازىرە»گە ئۆتۈش قىسقا ۋاقىتتا ئالتە خانىلىق يۇلتۇزغا ئېرىشىشنىڭ مۇھىم سەۋەبى.

بۇ ئىككى ئىشنىڭ كېيىنكىلەرگە ئىلھامى

بىللە قارىساق، Agent ياسىغۇچىلار كۆزدىن قاچۇرىدىغان ئىككى ئاساس قەۋەتنى كۆرسىتىدۇ:

  • Adapter لايىھە پەلسەپىسىسىزنىڭ N سۇپىنى ئاسان قوللىشىڭىز ياكى N سۇپىنىڭ N شاخنى بوغۇپ قويۇشىنى بەلگىلەيدۇ
  • Skill ھاياتلىق دەۋرىAgent نىڭ كۆپ ئىشلەتكەنسېرى قولايلىق ياكى ئارتۇقچە تەكرار بولۇشىنى بەلگىلەيدۇ

بۇ ئىككىسى تىل، stack ۋە تۈردىن ھالقىغان تۈپ ئۇسۇل. TypeScript / Python / Go دا ئىجراسى ئوخشىمىسىمۇ، بۇ ئىككى قەۋەتنى چۈشەنسىڭىز تۈرنىڭ يولى ئېنىقلىشىدۇ.

قوشۇمچە: OpenClaw TypeScript تا، Hermes Python دا، HexClaw Go دا يېزىلغان؛ ئاستىدا يەنە پۈتۈنلەي ئۆزى ياسالغان Go Agent ماتورى Hexagon Agent(ئامبار نامى hexagon، ئۆتكەن يىلدىن باشلاپ ياسىلىۋاتىدۇ) بار. تىل stack ى، ماتور، ئورۇنلاشتۇرۇش شەكلى باشقا —سېلىشتۇرغىلى بولىدىغىنى ئىنژېنېرلىق مەسىلىسى؛ بىۋاسىتە كۆچۈرگىلى بولمايدىغىنى كود ۋە ئىگىدارلىق. بۇ ماقالە سىرتقى تۈرلەر ئوتتۇرىسىدىكى ئەسلىلىك تالاش-تارتىشىغا ھۆكۈم قىلمايدۇ، پەقەت ئوچۇق ماتېرىيالدىكى قۇرۇلما تاللىشىنى سۆزلەيدۇ. HexClaw غا چۈشۈرگەندە يەنىلا ئۆزىمىزنىڭ Go ماتورى، ئۈستەل يۈزى شەكلى ۋە بىخەتەرلىك چېكى ئىچىدە قايتا ئىجرا قىلىش كېرەك.

«يېزىشقا بولىدىغان ئىجرا مۇھىتى»نى HexClaw قانداق قىلىدۇ؟

«Skill ئىشلىتىلگەنسېرى توغرىلىنامدۇ؟» دېگەن مەسىلىنى HexClaw ئۆز يولىدا قىلىپ كېلىۋاتىدۇ؛ نامى Skill نىڭ يېپىق ئۆزلۈكىدىن ئۆگىنىشى، v0.4.x تا تەدرىجىي ئەمەلگە ئاشىدۇ.

نىشان روشەن:Skill ئىشلىتىلگەنسېرى توغرىلانسۇن。

ئەمما ئىجرا جەھەتتە HexClaw ئاستىراق، لېكىن مۇقىمراق يولنى تاللىدى.

Hermes Python يولىدا: Agent ئىجرا جەريانىدا يېتەرلىك ياخشى نەتىجە كۆرمىسە، ئۆزى ياماق كود ياساپ ھەرىكەتچان ئىقتىدار ئامبىرىغا يازىدۇ، كېيىن بىۋاسىتە چاقىرىدۇ. پۈتۈنلەي ئاپتوماتىك، تېز ئۆگىنىدۇ؛ Python نىڭ ئىجرا ۋاقتىدا ئۆزىنى ئۆزگەرتىشكە ماس ھەرىكەتچان تەبىئىتىگە ئۇيغۇن.

HexClaw Go يولىدا، شۇڭا v0.4.x ئاددىي، ئەمما Go ئىنژېنېرلىق پەلسەپىسىگە ماس ئۇسۇلغا مايىل: ھازىرقى SkillWriter يېڭى Skill قۇرالايدۇ، يېزىشتىن بۇرۇن بىخەتەرلىك سىكاننېرى بار. كېيىنكى قەدەمدە تېخىمۇ تولۇق ئايلىنىشقا ئۇلىنىدۇ: Skill ئىجراسىدىن كېيىن LLM-as-judge نومۇر بېرىدۇ، يېتەرلىك بولمىسا كۆرۈپ چىقىشقا بولىدىغان v2 لايىھەسى ياسىلىدۇ؛ ئىجرا مۇھىتى ئەسلى Skill نى جىمجىت بېسىۋەتمەيدۇ. ئۆزىڭىز ئېچىپ كۆرۈڭ؛ ياخشى بولسا skills مۇندەرىجىسىگە قوشۇڭ، ياخشى بولمىسا ئۆچۈرۈڭ؛ بىر كۈنى پۇشايمان بولسىڭىز،git ئارقىلىق قايتۇرسىڭىزلا ئەسلىگە كېلىدۇ.

ئاستىراق بولسىمۇ پايدىسى ئېنىق —Agent نىڭ ئۆزىگە قىلغان ئۆزگىرىشىنى ھەر ۋاقىت كۆرەلەيسىز، ئۆزگەرتەلەيسىز، توسىيالايسىز. ئۇزۇن مۇددەت ئىشلىتىدىغان ئۈستەل يۈزى خىزمەت مۇھىتى ئۈچۈن بۇ «كۆرۈنۈپ تۇرىدىغان ئۆزلۈكىدىن تەرەققىيات» جىمجىت ئەقىللىق بولۇشتىن خاتىرجەمراق.

يەرلىك خىزمەت ئۈستىلى يولىدا يەنە ئىككى ئىشنى تولدۇرۇش كېرەك:

بىرىتەدرىجىي يۈكلەش. Skill كۆپەيگەندە ھەممىسىنى ھەر قېتىم context قا قاچىلىغىلى بولمايدۇ. شۇڭا قوزغالغاندا پەقەت ئىنتايىن يېنىك Skill كۆرسەتكۈچى (ھەر بىرى تەخمىنەن 20 token) يۈكلىنىدۇ، ھەقىقىي لازىم بولغاندىلا ئېچىلىدۇ.

يەنە بىرىبىرلەشمە ئۆگىنىش. يەككە Skill نىڭ ئۆسىشى بىرىنچى قەۋەتلا. دائىم ئالدى بىلەن A، ئاندىن B، ئاندىن C چاقىرىدىغانلىقىڭىز بايقالسا، HexClaw بۇ تەرتىپنى meta-Skill لايىھەسىگە ئايلاندۇرۇپ سىزگە كۆرسىتىدۇ. ساقلاش-ساقلىماسلىقنى يەنىلا ئۆزىڭىز قارار قىلىسىز.

بۇ ئىككىسى «يېزىشقا بولىدىغان ئىجرا مۇھىتى»دەك دىققەت تارتماسلىقى مۇمكىن، ئەمما Agent بىلەن ھەر كۈنى ھەقىقىي ئىش قىلىدىغانلارغا «ھەممىنى تولۇق ئاپتوماتىك قىلىپ بېرىش»تىن قولايلىقراق بولۇشى مۇمكىن.

v0.4.x تا تەييارلىنىۋاتقان باشقا «ئاساسىي قۇرۇلۇش»لار

ھالەت باياناتى: تۆۋەندىكىلەر v0.4.x يول خەرىتىسى؛ بەزىسى يەرلىك ئېچىشتا دەلىللەنگەن، بەزىسى كېيىنكى release نىڭ نىشانى. ھازىرقى v0.3.12 ئېلان نۇسخىسى بۇلارنىڭ ھەممىسىنى ئۆز ئىچىگە ئالمايدۇ. كونكرېت ھالەت ئۈچۈن CHANGELOG.md ۋە Release نى ئاساس قىلىڭ.

Skill ئايلىنىشىدىن باشقا v0.4.x تا يەنە بەزى ئىشلار قىلىنىۋاتىدۇ. يېڭىچە ئىقتىدار نۇقتىسى ئەمەس، بەلكى«ئۇزۇن مۇددەت ئىشلىتىلىدىغان Agent»قا ئاساسىي ئىنژېنېرلىق ئىقتىدارى تولدۇرۇش——

  • Agent ئىستراتېگىيە ھالىتىنى يوللاش. Hexagon Agent ماتورىدا ReAct، Plan-and-Execute، Reflection، Deep، Supervisor، Sequential، Parallel، Loop قاتارلىق قۇرۇلمىلار بار. hexclaw نىڭ v0.4.x ى ئالدى بىلەن ھازىرقى ReAct ماتورىغا auto / react / plan-execute / reflection تۆت ئىستراتېگىيەنى ئۇلايدۇ؛ ماتور ۋەزىپىگە قاراپ ئاپتوماتىك ئالماشتۇرىدۇ، تەڭشەكتە قولدا تاللاشقىمۇ بولىدۇ.
  • ئەستە ساقلاشقا يوليورۇق كىرگۈزۈشتىن مۇداپىئە. Agent ئۇزۇن ئىشلىتىلسە ئەستە ساقلاش يېڭى ھۇجۇم يۈزىگە ئايلىنىدۇ. memory غا XML بەلگىسى ۋە system note قوشۇپ، مودېلغا «بۇ پەقەت پايدىلىنىش ماتېرىيالى، يېڭى يوليورۇق ئەمەس»نى بىلدۈرىدۇ.
  • خاتالىق تۈرلەش ۋە دەرىجە تۆۋەنلىتىش ئىستراتېگىيەسى. 429، 402، 503 ئەھۋاللىرىدا ئاددىي قايتا سىناشلا ئەمەس؛ سەۋەبىگە قاراپ چېكىنىش، كىنىشكا ئالماشتۇرۇش، context قىسقارتىش، Provider ئالماشتۇرۇش يوللىرىنى تاللايدۇ.
  • مودېلنىڭ قورال چاقىرىش ئىقتىدارىنى بايقاش. بەزى يەرلىك مودېل قورال چاقىرغاندەك «ئويۇن قويىدۇ»، ئەمەلىيەتتە چاقىرمايدۇ. كىچىك تەكشۈرۈش قوشۇپ تەڭشەكتە ✅ / ⚠️ / ❌ بەلگىسى كۆرسىتىلىدۇ، خاتا يېتەكلەشتىن ساقلايدۇ.
  • MCP ئىجرا ۋاقتى باشقۇرۇشى. MCP server نى ئىجرا ۋاقتىدا قوشۇش / چىقىرىۋېتىش بولىدۇ، نورمالدا يېڭى server ئۈچۈن قايتا قوزغىتىش ھاجەتسىز؛ ئۈزۈلگەن ئۇلىنىش ھەر 30 سېكۇنتتا تەكشۈرۈلۈپ قايتا ئۇلىنىدۇ.

ئاڭلىماققا ھەممىسى «ئىنژېنېرلىق» ئىش، ئەمما يەرلىك خىزمەت ئۈستىلىنى ئۇزۇن مۇددەت ئىشلەتكىلى بولۇش كۆپ جەھەتتە مۇشۇ كىچىك نەرسىلەرگە باغلىق.

شۇڭا مەن بىخەتەرلىك چېكىگە تېخىمۇ ئەھمىيەت بېرىمەن. Agent قانچە قابىلىيەتلىك بولسا، ئىجازەتنى شۇنچە باشقۇرۇش كېرەك: قورال تەستىقى، MCP بۇيرۇق ئاق تىزىملىكى، Skill يېزىشتىن بۇرۇن سىكاننېرلاش، ئەستە ساقلاشقا يوليورۇق كىرگۈزۈشتىن مۇداپىئە، خاتالىق دەرىجىسىنى تۆۋەنلىتىش. دىققەتنى ئەڭ تارتماسلىقى مۇمكىن، ئەمما يەرلىك Agent نى ماشىنىڭىزدا ئۇزۇن ئىجرا قىلغىلى بولۇشنى بەلگىلەيدۇ.

ئۈچ يولنى نەزەرىيە جەھەتتىن قانداق بىرلەشتۈرىمىز؟

تۆۋەندىكىسى قۇرۇلما جەھەتتىكى بىرلەشتۈرۈش، ئۈچ تەرەپنىڭ رەسمىي بىرلەشتۈرۈشى بار دېگەنلىك ئەمەس. ئىنژېنېرلىق stack نۇقتىسىدىن بىر رەسىمگە قويغىلى بولىدۇ، چۈنكى چېگرىلىرى ئەسلىدىن قاپلاشمايدۇ.

يېقىنقى يىللاردا Agent تۈرلىرىنىڭ بىرلەشتۈرۈلۈشىنىڭ تۈپ سەۋەبى ھەممە بىر رامكا ئىشلەتكەنلىكى ئەمەس، بەلكى MCP، HTTP / SSE، OpenAI-compatible قاتارلىق ئوچۇق كۆرۈنمە يۈزلەرنىڭ ئورتاق تىلغا ئايلانغانلىقى.

ئاددىي ئېيتساق: HexClaw يەرلىك ئاساس، Hermes چوڭقۇر ۋەزىپىگە، OpenClaw نەتىجىنى ھەر پاراڭ كىرىشىگە يەتكۈزۈشكە مەسئۇل.بىر-بىرىنى ئالماشتۇرۇش ھاجەتسىز، كۆرۈنمە يۈز ئۇلانسا ھەر بىرى ئۆز كۈچلۈك ئىشىنى قىلىدۇ.

ئەمەلىيەتكە يېقىن ھەمكارلىق شەكلى:

  • يەرلىكتە دائىم ئوچۇق ماشىنىدا (Mac mini / NUC / كىچىك server) HexClawئىجرا بولىدۇ؛ يەرلىك Go sidecar، Ollama يەرلىك مودېلى،MCP مەركىزى، بىلىم ئامبىرى ۋە Skill نىڭ ماكانى بولىدۇ. يەرلىك REST / WebSocket / MCP SSE قاتارلىق ئوچۇق كۆرۈنمە يۈزلەر بىلەن ئىقتىدار بېرىدۇ.
  • پىلانلاش ۋە ئەكس ئەتتۈرۈش تەلىپى يۇقىرى ئۇزۇن ۋەزىپە ئۆلچەملىك OpenAI-compatible كېلىشىمى ئارقىلىق Hermesقا ھاۋالە قىلىنىدۇ، ئۇ Skill قايتا يېزىش ۋە كۆپ باسقۇچلۇق تەپەككۇرغا مەسئۇل.
  • كۆپ سۇپىغا تارقىتىش، كۆپ ھېسابات ماترىتساسى، IM پاراڭ كىرىشى ئۈچۈن OpenClawئىشلىتىلىدۇ؛ HexClaw ئۈستۈنكى نەتىجىنى HTTP ئارقىلىق يوللايدۇ، OpenClaw ئۆزىنىڭ Adapter Capabilities ى بىلەن دەرىجە تۆۋەنلىتىش ۋە كۆرسىتىشنى قىلىدۇ.

ئۈچىنىڭ ئالاقىسى تەييار ئوچۇق كېلىشىملەر (HTTP، WebSocket، SSE، MCP، OpenAI-compatible) ئارقىلىق، بىر-بىرىگە باغلاپ قويۇش يوق.چېگرا ئېنىق، ھەر بىرى ئۆز ئالدىغا ئىجرا بولىدۇ، مەسىلە چىقسامۇ ئاسان تېپىلىدۇ。

ئاخىرقى سۆز

OpenClaw كىرىشنى ئۇلايدۇ، Hermes تەجرىبە ساقلايدۇ، HexClaw يەرلىكنى قوغدايدۇ.

2026-يىلى ئوچۇق مەنبە Agent ساھەسىدە OpenClaw ۋە Hermes ئايرىم بىر ئاساس قەۋىتىنى ئالغا سۈردى: بىرى «كۆپ سۇپا ئىقتىدارىنىڭ بايانلىق ئابستراكسىيەسى»، بىرى «Skill ھاياتلىق دەۋرىنى ھەرىكەتچان قىلىش». ھازىر بۇ ئىككىسىنى ھەقىقىي پۇختا قىلغان تۈرلەر تېخى كۆپ ئەمەس.

HexClaw نىڭ يولى — ئۈستەل يۈزى خىزمەت مۇھىتى، يەرلىكتە دائىم ئىجرا قىلىش، Go يەككە ئىككىلىك ھۆججەت، Sidecar قۇرۇلمىسى، ئالتە ئامبارلىق قەۋەت — باشقا بىر تۈپ مەسىلىنى ھەل قىلىدۇ: «يەرلىك Agent خىزمەت ئۈستىلى»نى مەشغۇلات باشقۇرۇشنى بىلمەي تۇرۇپ ئىشقا كىرىشتۈرۈش. كېيىنكى نەچچە نۇسخا كونكرېت كۆرۈنۈشلەرگە چوڭقۇرلايدۇ، كېيىنكى ماقالىدە سۆزلەيمىز.

بۇ يەرگە قەدەر ئوقۇپ، Bot ماترىتساسى ياكى تەتقىقات تىپىدىكى ئۆزلۈكىدىن ئۆگىنىش رامكىسىدىن كۆرە، ئۆز كومپيۇتېرىڭىزدا ئۇزۇن ئاچقىلى بولىدىغان يەرلىك Agent خىزمەت ئۈستىلى لازىملىقىنى بايقىسىڭىز، GitHub Release دىن ماس ئورنىتىش بوغچىسىنى ئېلىڭ:

DMG / MSI / AppImage：github.com/hexagon-codes/hexclaw-desktop/releases

macOS ئىشلەتكۈچىلىرى بىر چېكىشلىك script بىلەنمۇ ئورنىتالايدۇ:

curl -fsSL https://raw.githubusercontent.com/hexagon-codes/hexclaw-desktop/main/install.sh | bash

كېڭەيتىپ ئوقۇش— HexClaw يۈرۈشلۈكىنىڭ ئالدىنقى ماقالىلىرى:

  1. Claude Code SOP — لايىھە يېتەكچىلىكى × سىناقنى تاماملاش × كۆپ Agent ھەمكارلىقى
  2. قۇرۇلما تەپسىلىي چۈشەندۈرۈشى — بىر ئادەم × Claude Code × 5 ئاي × 6 ئامبار
  3. راك بېقىشتىن قىسقۇچپاقا بېقىشقىچە — مەھسۇلات ئېلانى / OpenClaw تېمىسىغا جاۋاب
  4. تەپەككۇر جەريانى — Qwen / Gemma / DeepSeek-R1 نىڭ ئاخىرقى بىر كىلومېتىرىنى ئېچىش
  5. تولۇق قوللانما — 5 مىنۇتتا نۆلدىن ئىش قىلالايدىغان يەرلىك AI Agent قا
  6. ئىلگىرىكى رەھبەر Skill ى — رەھبەرنى AI Skill غا ئايرىپ چىقىرىش
