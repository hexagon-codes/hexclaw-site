HexClaw 河蟹开源AI：从“养龙虾”到“养河蟹”

你养龙虾🦞了吗？从今天起，🦞龙虾能帮你干的活，俺🦀河蟹也能帮你干，但河蟹想做的，不只是“接住一次对话”，而是接住持续的工作任务。

最近 AI 圈最火的动物，不是猫，也不是狗，而是一只"龙虾"。

OpenClaw 之所以会火，不只是因为它"能聊天"，而是因为它第一次把很多人对 AI Agent 的想象，变成了一个真正住进工作流里的助手。它能进 Telegram、Slack、Discord、Lark 这些你本来就在用的入口，能统一收件箱，能自动回消息，能操作浏览器、控制桌面、跑任务，而且还强调本地运行、隐私优先、多模型和技能扩展。

对很多人来说，龙虾第一次把"AI 助手"从一个聊天框，变成了一个真的会做事、一直在线、还有点个性的数字同事。这也是为什么最近网上会有那么多围绕它的段子和热梗："你养龙虾了吗"、龙虾帽、钳子手势、"一人公司 + 一只龙虾"。

说到底，大家真正热衷的不是一个吉祥物，而是它背后那种很强的感受：

  • AI 不再只是回答问题
  • AI 开始真的"动手"
  • AI 终于像一个助手一样开始干活

但河蟹想解决的，是另一个层级的问题。

龙虾更像一个好用、好玩、能立刻上手的个人 AI 助手；河蟹要做的，则是一个面向真实工作流、能沉淀知识、能编排智能体、能追踪执行链路的本地 AI Agent 工作台。

HexClaw 河蟹不是把 AI 塞进一个聊天入口里就结束了，而是把 聊天 和 IM 通道 作为任务入口，把 知识库 / 智能体 / 集成 作为能力底座，再把 日志 和 排障闭环 补上。

更准确地说，HexClaw 的官网一直在强调一件事：它不是一个"再包一层聊天框"的 AI 产品，而是一款基于自研 Hexagon AI Agent 引擎、开箱即用的 AI Agent 桌面客户端。它强调的不是把能力堆满，而是把能力真正组织起来：多 Agent 协作、可视化工作流、RAG 知识库、MCP 工具协议、IM 通道、实时日志，功能一个不少，但数据尽量都留在本地。

如果把两者放在一起看，区别会更清楚：

  • 龙虾让 AI 像助手一样开始干活
  • 河蟹让 AI 像工作台一样稳定运转

再展开一点，河蟹更关心的是这些问题：

  • 不只是让 AI 接住一次对话，而是接住持续的工作任务
  • 不只是让 AI 进入一个入口，而是让 聊天 / IM 通道 / 自动化 汇到同一条执行链路
  • 不只是让 AI 会调用工具，而是把 知识库 / 智能体 / 集成 / MCP / 自动化 组织成闭环
  • 不只是"会做"，还要"能看、能查、能排障、能长期维护"
  • 不只是强调本地运行，还强调 sidecar 架构、本地部署、零云端依赖、数据完全私有

所以龙虾像一只把 Agent 热潮彻底点燃的明星物种，而河蟹更像一只真正能横着走进你桌面工作流里的生产力物种。

如果只用一句话来理解 HexClaw，可以先记住这句：

HexClaw 河蟹不是单一聊天窗口，而是一个以聊天和 IM 通道为任务入口、以知识库 / 智能体 / 集成为能力底座、以日志为排查闭环的本地 AI Agent 工作台。

官网首页把它概括得很清楚：基于自研 Hexagon AI Agent 引擎，HexClaw 是一款开箱即用的 AI Agent 桌面客户端。本地部署、数据私有、全栈开源。

还有一点很重要，也是官网和 README 一直在反复强调的：河蟹不是一个孤立的单体 App，而是 hexagon-codes 团队打造的全栈开源 AI Agent 生态的一部分。

这套生态不是只开源一个桌面壳，而是从底层到上层都分层解耦：

  • toolkit：基础设施，负责日志、配置、HTTP 和并发等公共能力
  • ai-core：AI 能力底座，负责 LLM Provider、Embedding、Function Calling、记忆和向量能力
  • hexagon：自研 Agent 引擎，负责 ReAct、Plan-and-Execute、Workflow 和 Tool 调度
  • hexclaw：后端 Sidecar，负责 RESTful API、RAG 检索、Cron 调度、会话持久化和引擎集成
  • hexclaw-desktop：桌面客户端，负责本地原生运行、Sidecar 集成和跨平台交付
  • hexclaw-ui：Web 客户端，负责产品主界面与桌面端 UI 复用
  • hexagon-ui：Agent 观测台，负责执行链路追踪、推理回放和性能观测

这也是河蟹和很多"只开源一个入口应用"的产品不太一样的地方。它背后是一整条完整的开源工具链，而且采用 Apache-2.0 协议发布。你看到的不只是一个能下载的客户端，更是一套可以审计、可以理解、可以复用、也可以持续演进的 AI Agent 工程体系。

从产品角度看，这意味着：

  • 你可以把它当成开箱即用的桌面客户端直接使用
  • 也可以把它当成一个本地优先、数据私有的 AI Agent 平台
  • 甚至可以继续往下理解它背后的引擎、后端、工具协议和观测体系

开源生态

河蟹的一个很大特点，是它不是"只开源一个桌面壳"，而是从底层基础设施到桌面客户端，整条链路都在开源。

官网关于页给它的定义是：由 hexagon-codes 团队打造的全栈开源 AI Agent 生态。

README 和官网仓库对这条生态链的描述也很一致：

toolkit -> ai-core -> hexagon -> hexclaw -> hexclaw-desktop / hexclaw-ui / hexagon-ui

这条链路里，每一层都有明确职责：

  • toolkit：基础设施，负责日志、配置、HTTP、并发和错误链等公共能力
  • ai-core：AI 能力底座，负责 Provider 适配、Embedding、记忆和向量能力
  • hexagon：自研 Agent 引擎，负责 ReAct、Plan-and-Execute、Workflow 和 Tool 调度
  • hexclaw：后端 Sidecar，负责 RESTful API、RAG 检索、Cron 调度、会话持久化和引擎集成
  • hexclaw-desktop：桌面客户端，负责本地原生运行、Sidecar 集成和跨平台交付
  • hexclaw-ui：Web 客户端，负责产品主界面与桌面端 UI 复用
  • hexagon-ui：Agent 观测台，负责执行链路追踪、推理回放和性能观测

这也是河蟹和很多"只开源一个入口应用"的产品不太一样的地方。它背后是一整条完整的开源工具链，而且采用 Apache-2.0 协议发布。你看到的不只是一个能下载的客户端，更是一套可以审计、可以理解、可以复用、也可以持续演进的 AI Agent 工程体系。

从这个角度看，河蟹不只是一个产品，也是一套公开生长的工程生态：

  • 对普通用户，它是开箱即用的桌面客户端
  • 对技术用户，它是本地优先、数据私有的 AI Agent 平台
  • 对开发者，它也是一套可以继续向下理解和接入的开源能力栈
